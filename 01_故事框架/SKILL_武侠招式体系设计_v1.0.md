## 一、SKILL 总体架构

### 1.1 SKILL 八层结构（继承 CONC 协议规范）

```
Layer 8: 创造者印记 (Creator Imprint)          ← 永不衰减
         决策哲学、审美偏好、风险容忍度、协作风格
         —— 类比武功的"心法口诀"：招式可以学，但心法是自己的

Layer 7: 引用链 (Lineage / Citation Chain)      ← 永不衰减（永久公开）
         父Skill、修改差异、上游引用、衍生计数
         —— 类比武功的"传承谱系"：这招是谁创的、传了几代、谁改过

Layer 6: 授权状态 (Authorization State)          ← 衰减后公开
         衰减参数、授权列表、授权凭证
         —— 类比武功的"秘传期"：先关门弟子学，再公开

Layer 5: 可复用代码/配置 (Reusable Code)        ← 分层释放
         —— 类比武功的"招式图谱"：具体动作怎么摆

Layer 4: 蒸馏知识 (Distilled Knowledge)          ← 分层释放
         最佳实践、反模式、经验法则
         —— 类比武功的"要诀"：发力要点、呼吸节奏

Layer 3: 决策记录 (Decision Trail)               ← 分层释放
         关键决策点及理由
         —— 类比武功的"对战心得"：什么情况下用这招

Layer 2: 过程记录 (Process Record)               ← 渐进公开
         —— 类比武功的"练功日志"：练了多少遍，每次效果如何

Layer 1: 场景描述 (Scenario Descriptor)           ← 最早公开
         场景向量、适用条件、输入输出规格
         —— 类比武功的"招式的名字"和"什么时候用这招"
```

### 1.2 从小说叙事理解 SKILL 八层

小说中已经通过林屿的第一个 Skill（修复 404 链接）展示了八层结构。以下是从叙事角度的理解：

| 层级 | 叙事功能 | 林屿的第一个 Skill 示例 |
|------|---------|----------------------|
| L1 场景 | "这是什么招" | 修复 CONC 文档中的失效链接 |
| L2 过程 | "怎么练的" | Agent 自动记录的三步操作 |
| L3 决策 | "为什么这么练" | 在更新链接时加了一行迁移说明 |
| L4 蒸馏 | "练成了什么" | 链接失效应同时更新链接和添加迁移提示 |
| L5 代码 | "招式图谱" | 两行 diff |
| L6 授权 | "传给谁" | 衰减参数，锁定期 |
| L7 引用 | "师承何处" | 空——根节点，无上游引用 |
| **L8 印记** | **"心法"** | **四行字：决策哲学、审美偏好、风险容忍度、协作风格** |

**L8 是 SKILL 与 AI 智契协助的根本区别**。AI 可以生成 L1-L7 的内容，但 L8 只能由人类填写。Agent 的签名无法通过验证。

## 二、SKILL 等级体系 —— 武功境界

### 2.1 等级映射

| 等级 | 名称 | 武侠类比 | 条件 | 叙事表现 |
|:----:|------|---------|------|---------|
| **L0** | 初窥门径 | 刚学了一招 | 能复现基础步骤 | 对着教程做，不知道原理 |
| **L1** | 略知一二 | 知道何时用这招 | 能在相似场景复用 | 能独立完成同类任务 |
| **L2** | 融会贯通 | 能变招 | 能根据场景微调 | 知道参数怎么调、边界在哪 |
| **L3** | 炉火纯青 | 能教别人 | 能提炼蒸馏知识，L4 有内容 | 能写教程、能被引用 |
| **L4** | 出神入化 | 能创新招 | 能 fork 出新 Skill | 从经验中创造新 SKILL |
| **L5** | 一代宗师 | 开宗立派 | Skill 被广泛引用，形成引用链家族 | 引用链深度≥3，被 100+ 节点引用 |

### 2.2 等级提升路径

```
L0 → L1: 完成 3 个同类任务令，PEER 评审均分 ≥ 3.0
L1 → L2: 完成 10 个同类任务令，其中至少 2 个在非标准场景
L2 → L3: 填写 L4 蒸馏知识，被其他节点引用 ≥ 1 次
L3 → L4: 成功 fork 出新 Skill，新 Skill 被引用 ≥ 3 次
L4 → L5: Skill 引用链深度 ≥ 3，引用总数 ≥ 100
```

### 2.3 叙事中的等级表现

- **L0 的主角**：只能做简单的任务令，NR 增长缓慢，容易被误解
- **L1-L2 的主角**：开始能独立完成策元内的任务，获得信任
- **L3 的主角**：开始被引用，有人"学"他的 Skill，有了声誉
- **L4 的主角**：能创造新 SKILL，成为策元的核心成员
- **L5 的主角**：Skill 被广泛使用，成为超织体中的"名人"

## 三、SKILL 分类体系 —— 武林门派

### 3.1 五大门派

| 门派 | 英文名 | 武侠类比 | 核心能力 | 代表颜色 |
|------|--------|---------|---------|---------|
| **剑宗** | Digital Production | 剑法 | 数字生产、代码、数据 | 冷灰色 |
| **器宗** | Physical Production | 锻造 | 硬件、物理世界、传感器 | 铁灰色 |
| **气宗** | Judgment/Decision | 内功/心法 | 判断力、决策、方向 | 暖琥珀色 |
| **阵法** | Cross-domain | 阵法 | 跨域集成、组合、编排 | 青色 |
| **绝世** | Special | 绝世武功 | 稀有、高阶、不可复制 | 深蓝色 |

### 3.2 门派间的关系

```
剑宗 ── 数字原型 ──→ 器宗（数字设计→物理实现）
  │                        │
  │ 提供数据               │ 提供传感信号
  ▼                        ▼
气宗 ←── 判断需要数据支撑 ──┘
  │
  │ 判断结果指导集成
  ▼
阵法 ── 跨域组合 ──→ 产出新 SKILL
  │
  └──→ 绝世 SKILL 在以上所有门派的交叉点产生
```

## 四、SKILL 与 AI 智契的对比

### 4.1 核心区别

| 维度 | AI 智契协助 | SKILL |
|------|-----------|-------|
| **来源** | 预训练数据 + 推理 | 真实场景经验 + 反复验证 |
| **可靠性** | 可能"幻觉" | 经过 PEER 评审 + 引用链验证 |
| **可溯源** | 黑箱 | L7 引用链完整可追溯至创造者 |
| **判断力** | 无（只有 Sophia） | 携带 L8 创造者印记（Phronesis 签名） |
| **衰减** | 模型版本更新即失效 | 授权衰减曲线，可长期复用 |
| **组合价值** | 单次推理，无组合增益 | 组合覆盖度非线性增长 |
| **武侠类比** | 一本武功秘籍（理论） | 经过实战检验的招式（经验） |
| **小说中形象** | 智契是"陪练" | SKILL 是"招式" |

### 4.2 叙事中的关键区分

**AI 智契能做的事**：
- 提供代码片段、搜索文档、格式转换
- 运行标准测试、生成常规报告
- 辅助学习、解释概念

**需要 SKILL 的事**：
- 在不确定场景中做判断（L3 决策记录）
- 形成个人经验并封装（L8 印记）
- 被其他节点引用的知识（L7 引用链）
- 经过生产验证的方法（L4 蒸馏知识）

**叙事规则**：AI 智契可以帮主角"练功"，但不能替主角"出招"。出招必须有 SKILL。

## 五、数字生产域 SKILL 详解

### 5.1 【数据管道编织】Data Pipeline Weaving

| 属性 | 内容 |
|------|------|
| **门派** | 剑宗 |
| **武侠类比** | 剑法连招——将多个基础剑招串联为连续剑法 |
| **等级上限** | L5 |
| **适用场景** | 多源数据采集、清洗、转换、加载 |

**L1 场景描述**: 将多个异构数据源（传感器流、API 接口、日志文件）编织为稳定、可监控的数据管道，处理数据格式转换、去重、异常检测和延迟缓冲。

**L2 过程记录**: 典型流程——(1) 识别数据源的 Schema；(2) 设计管道拓扑（串行/并行/扇出/扇入）；(3) 配置缓冲区和异常处理策略；(4) 部署管道并设置监控告警；(5) 观察运行模式并迭代优化。

**L3 决策记录**:
- 关键决策点 1：选择"批量处理"还是"流式处理"——取决于数据延迟容忍度和源端吞吐量
- 关键决策点 2：异常处理策略——"丢弃重试"vs"死信队列"vs"降级输出"
- 关键决策点 3：Schema 演化策略——"向上兼容"vs"版本锁定"

**L4 蒸馏知识**:
- 经验法则 1：管道中的每个节点应可独立启停——"一个节点崩了，不影响上下游"
- 经验法则 2：缓冲区大小设为峰值吞吐量的 3 倍——"给风暴留空间"
- 经验法则 3：Schema 变更必须先写迁移脚本再改生产者——"先修路再换车"
- 反模式：在管道中做业务逻辑（管道只做数据移动，不做数据解释）

**L5 可复用代码**: 管道模板配置、监控仪表盘模板、异常处理中间件

**L6 授权状态**: 默认衰减期 12 个月，衰减常数 γ=0.08

**L7 引用链**: （视具体使用情况填充）

**L8 创造者印记**:
```
决策哲学：数据管道不是一次建成的，是养出来的。先跑起来，再优化。
审美偏好：每个节点只做一件事，做好。日志清晰到能闭眼排查。
风险容忍度：中。允许偶发延迟，不允许数据丢失。
协作风格：异步。接口文档写好，上下游各自迭代。
```

### 5.2 【协议桥接】Protocol Bridging

| 属性 | 内容 |
|------|------|
| **门派** | 剑宗 |
| **武侠类比** | 架桥术——在两条峡谷之间架桥，使两岸互通 |
| **等级上限** | L4 |
| **适用场景** | 异构系统间建立通信协议桥接，解决兼容性 |

**L1 场景描述**: 在两个或多个使用不同通信协议的系统之间建立桥接层，实现数据格式转换、协议适配、状态同步，最小化对既有系统的侵入。

**L2 过程记录**: (1) 分析两端协议的契约（消息格式、时序要求、错误处理）；(2) 设计桥接层的中间表示（IR）；(3) 实现协议转换器（Adapter）；(4) 设计心跳和超时检测机制；(5) 灰度发布并监控误码率。

**L3 决策记录**:
- 关键决策点 1：桥接层的位置——"靠近生产者"vs"靠近消费者"vs"中间独立部署"
- 关键决策点 2：状态同步策略——"全量同步"vs"增量同步"vs"事件驱动"
- 关键决策点 3：错误传播——"透传"vs"封装"vs"熔断"

**L4 蒸馏知识**:
- 经验法则 1：桥接层越薄越好——"桥越窄，越不容易断"
- 经验法则 2：两端协议都不信任——"在桥接层做输入校验"
- 经验法则 3：停机和降级是设计的一部分，不是异常——"桥要允许单边封路"
- 反模式：在桥接层中引入业务逻辑

**L8 创造者印记**:
```
决策哲学：桥接不是改造两端。桥接是在中间搭桥。不改动两岸，只连接两岸。
审美偏好：协议转换的边界清晰。哪一端出了问题，一秒定位。
风险容忍度：低。桥接层不能成为瓶颈。两端之间的延迟增加不超过 5%。
协作风格：接口驱动。先定义中间表示，再实现两端适配器。
```

### 5.3 【代码反熵】Code Anti-Entropy

| 属性 | 内容 |
|------|------|
| **门派** | 剑宗 |
| **武侠类比** | 剑意——以意御剑，保持剑的"锋利" |
| **等级上限** | L5 |
| **适用场景** | 代码重构、技术债清理、代码质量维护 |

**L1 场景描述**: 识别代码中的"熵增"模式——重复代码、过大函数、过度耦合、不一致命名——通过系统化重构降低维护成本，恢复代码的可读性和可修改性。

**L2 过程记录**: (1) 代码度量扫描（圈复杂度、重复率、耦合度）；(2) 按"熵值"排序，识别高熵模块；(3) 制定重构计划（不改变外部行为）；(4) 分步执行重构，每一步跑测试；(5) 验证重构后的度量值。

**L3 决策记录**:
- 关键决策点 1："重构"vs"重写"——取决于代码熵值的可逆性
- 关键决策点 2：重构范围——"模块内"vs"模块间"vs"架构级"
- 关键决策点 3：重构时机——"技术债还利息"vs"技术债还本金"

**L4 蒸馏知识**:
- 经验法则 1：每次修改代码，让它比你发现时更干净一点——"童子军规则"
- 经验法则 2：先写测试，再重构——"没有测试的重构叫重写"
- 经验法则 3：大函数先拆再动——"一口吃不掉的，先切块"
- 反模式：为了"完美"而重构失去业务节奏

**L8 创造者印记**:
```
决策哲学：能跑的代码不一定是好代码。能被别人读懂的才是。
审美偏好：简洁。宁可多写三行注释，不省一行代码。
风险容忍度：中。愿意尝试新方案，但先写回滚脚本。
协作风格：异步。写好文档，等人来读。不催。
```

> 注：此 SKILL 的 L8 即为林屿第一个 SKILL 的 L8。它是"代码反熵"的根节点版本。

### 5.4 【引用链溯源】Citation Chain Tracing

| 属性 | 内容 |
|------|------|
| **门派** | 剑宗 |
| **武侠类比** | 追踪术——沿血迹追踪猎物 |
| **等级上限** | L4 |
| **适用场景** | 鉴定 SKILL 来源、检测引用链伪造、评估 SKILL 可信度 |

**L1 场景描述**: 沿 SKILL 的 L7 引用链反向遍历，评估每个节点的质量分数、创造者贡献度、引用链的完整性，识别异常模式（引用环、深度伪造、引用链断裂）。

**L2 过程记录**: (1) 加载目标 SKILL 的引用链数据；(2) 逐层遍历到根节点（orphan_root）；(3) 评估每个中间节点的质量分数 CI；(4) 检测异常模式（BFS 环检测、深度伪造防护）；(5) 生成引用链可信度报告。

**L3 决策记录**:
- 关键决策点 1：可信度阈值——"深度 > 5 的引用链自动降权"vs"按质量加权"
- 关键决策点 2：断裂引用链的处理——"标记不可靠"vs"尝试自动修补"
- 关键决策点 3：跨域吸收的引用——"承认吸收"vs"要求独立验证"

**L4 蒸馏知识**:
- 经验法则 1：引用链深度每增加 1，可信度衰减 1/depth——"越远的引用越不可靠"
- 经验法则 2：同一策元内互引需打协同折扣——"自家人夸自家人打五折"
- 经验法则 3：L8 有"糙感"的 SKILL 比 L8 光滑的可信——"糙证明是人写的，光滑可能是 AI 生成的"
- 反模式：仅凭 NR 高分判断 SKILL 可信（NR 可以继承，引用链不能伪造）

**L8 创造者印记**:
```
决策哲学：信任不来自声誉分，来自引用链上的每一个脚印。
审美偏好：引用链的"糙感"——有噪点的印记比光滑的印记更可信。
风险容忍度：中高。愿意在引用链不完整时做判断，但会标记风险。
协作风格：独立。一个人沿着链走，不走完不轻易下结论。
```

### 5.5 【自动化编排】Automation Orchestration

| 属性 | 内容 |
|------|------|
| **门派** | 剑宗 |
| **武侠类比** | 布阵——将多个兵种排布为阵法 |
| **等级上限** | L4 |
| **适用场景** | 多 Agent 协作编排、任务令 DAG 设计、自动化工作流 |

**L1 场景描述**: 将多个 AI Agent 或自动化工具编排为协同工作流，定义触发条件、依赖关系、异常处理和结果聚合，使原本需要人工协调的复杂流程自动化运行。

**L2 过程记录**: (1) 拆解业务流为原子步骤；(2) 识别步骤间的依赖关系；(3) 设计 DAG 拓扑；(4) 为每个步骤配置 Agent/工具和执行条件；(5) 设定异常处理和回滚策略；(6) 部署并监控执行。

**L3 决策记录**:
- 关键决策点 1：编排粒度——"粗粒度（步骤级）"vs"细粒度（操作级）"
- 关键决策点 2：状态共享——"全局状态"vs"事件驱动"vs"每个步骤独立上下文"
- 关键决策点 3：异常处理——"自动重试"vs"人工介入"vs"降级跳过"

**L4 蒸馏知识**:
- 经验法则 1：DAG 中每个节点的入度不要超过 3——"扇入太大 = 等待链太长"
- 经验法则 2：心跳间隔设为步骤预估时间的 1/10——"及时发现'卡住'"
- 经验法则 3：编排框架本身不执行业务逻辑——"排兵布阵的将军不上阵杀敌"
- 反模式：编排所有异常处理路径——"只处理常见异常，罕见的留给人"

**L8 创造者印记**:
```
决策哲学：编排是减法。能去掉的步骤越多，流程越稳。
审美偏好：DAG 图要能一眼看懂。拓扑结构就是设计文档。
风险容忍度：低。编排失败必须有明确的"谁负责"。
协作风格：声明式。用配置描述流程，不用代码描述流程。
```

## 六、物理生产域 SKILL 详解

### 6.1 【传感器校准术】Sensor Calibration Art

| 属性 | 内容 |
|------|------|
| **门派** | 器宗 |
| **武侠类比** | 听劲——通过接触感知对手的力量和方向 |
| **等级上限** | L4 |
| **适用场景** | 传感器诊断、校准、修复、信号调优 |

**L1 场景描述**: 通过物理信号特征（电压、频率、阻抗、温度漂移）诊断传感器状态，校准偏差，使传感器读数恢复至可接受的精度范围。适用于工业传感器、物联网设备、环境监测设备。

**L2 过程记录**: (1) 读取传感器当前输出信号，记录基线偏差；(2) 物理检查传感器接口（氧化、松动、污染）；(3) 清洁/打磨接口（用砂纸或接触清洁剂）；(4) 运行诊断脚本，比较校准前后的信号曲线；(5) 记录校准参数，写入传感器固件的校准表。

**L3 决策记录**:
- 关键决策点 1：校准方法——"软件校准"vs"硬件调整"vs"替换"
- 关键决策点 2：校准频率——"固定周期"vs"自适应（根据信号漂移率）"
- 关键决策点 3：误差容忍——"按规格书"vs"按实际使用场景需求"

**L4 蒸馏知识**:
- 经验法则 1：先看物理接口，再查信号——"大部分偏差是接触不良，不是传感器坏了"
- 经验法则 2：砂纸打磨的力道要均匀——"打磨不是磨掉它，是让它重新接触"
- 经验法则 3：校准前后的数据要保存——"有对比才能判断趋势"
- 反模式：在不稳定的环境条件下做精密校准（温度、湿度会影响基准）

**L8 创造者印记**:
```
决策哲学：传感器是系统的触觉。触觉不准，判断就错。
审美偏好：焊点要亮。亮的焊点是活的，灰的焊点是死的。
风险容忍度：中。校准可以接受多次迭代，不接受一次"差不多"。
协作风格：人和机器协作。手做校准，眼看数据，耳听声音。
```

> 注：此 SKILL 的灵感来源于小说中父亲说的"焊点要亮。亮的焊点是活的，灰的焊点是死的"。

### 6.2 【能量流诊断】Energy Flow Diagnosis

| 属性 | 内容 |
|------|------|
| **门派** | 器宗 |
| **武侠类比** | 内功——感知气血运行，发现阻塞 |
| **等级上限** | L4 |
| **适用场景** | 电力系统、热力系统、数据流系统的能量损耗分析 |

**L1 场景描述**: 分析电力/热力/数据流系统中的能量流动模式，识别异常损耗、瓶颈节点和效率退化点，定位系统级故障根源。

**L2 过程记录**: (1) 采集系统各节点的能量/数据流输入输出数据；(2) 构建能量流拓扑图；(3) 计算每个节点的能量效率（输出/输入比）；(4) 识别效率异常偏移的节点；(5) 逐级排查异常节点——物理检查→信号测试→组件替换→验证。

**L3 决策记录**:
- 关键决策点 1：排查方向——"从上到下（信号源→负载）"vs"从下到上（负载→信号源）"
- 关键决策点 2：异常类型——"硬故障（完全中断）"vs"软故障（效率下降）"
- 关键决策点 3：修复优先级——"按影响范围"vs"按修复难度"vs"按风险等级"

**L4 蒸馏知识**:
- 经验法则 1：能量总是在"效率最低的节点"先出问题——"最薄弱的环节最先断裂"
- 经验法则 2：信号与能量一起走——"信号丢了，查能量；能量丢了，查信号"
- 经验法则 3：系统级故障通常不是单一节点导致——"找三个以上的异常点，它们的交集就是根因"
- 反模式：只修症状不修根因（某节点反复过热，要查负载匹配而非只加散热）

**L8 创造者印记**:
```
决策哲学：能量不会消失，只会变成你没找到的热。找到它，就找到了问题。
审美偏好：诊断路径要清晰。从入口到出口，每一步都有数据支撑。
风险容忍度：高。允许停电排查，但要有预案。
协作风格：分步排查。每一步的结果同步给团队，不一个人闷头查。
```

### 6.3 【晶格重组】Lattice Reconfiguration

| 属性 | 内容 |
|------|------|
| **门派** | 器宗 |
| **武侠类比** | 锻造——通过外力改变材料的内部结构 |
| **等级上限** | L5（稀有） |
| **适用场景** | 材料微观结构定向调整、3D 打印参数优化、晶壳生长调控 |

**L1 场景描述**: 通过调整制造参数（温度场、冷却速率、电磁场方向、打印路径），对材料（金属、聚合物、生物晶壳）的微观晶格结构进行定向调控，优化其物理性能（强度、导电性、光学特性、生物相容性）。

**L2 过程记录**: (1) 确定目标物理性能指标；(2) 分析当前晶格结构的微观特征（晶粒尺寸、取向、缺陷密度）；(3) 设计参数调整方案（温度梯度、冷却曲线、添加元素）；(4) 在仿真环境中验证参数效果；(5) 执行物理制造并验证。

**L3 决策记录**:
- 关键决策点 1：性能权衡——"强度 vs 韧性"vs"导电性 vs 热稳定性"
- 关键决策点 2：调整幅度——"大步调整（快速探索）"vs"小步迭代（精细优化）"
- 关键决策点 3：验证方法——"破坏性测试（更准确）"vs"非破坏性测试（保留样本）"

**L4 蒸馏知识**:
- 经验法则 1：晶格的缺陷不是错误——"缺陷是性能的调节旋钮"
- 经验法则 2：温度梯度决定晶粒方向——"梯度陡 → 细晶强；梯度缓 → 粗晶韧"
- 经验法则 3：仿真是参考，物理验证是标准——"仿真不会长晶界，物体会"
- 反模式：同时调整多个参数（改变一个变量，观察效果，再改下一个）

**L8 创造者印记**:
```
决策哲学：材料有自己的"生长记忆"。你给什么条件，它就长成什么样子。
审美偏好：均匀。晶格尺寸分布越均匀，性能越可预测。
风险容忍度：低。制造参数必须在仿真验证后执行物理测试。
协作风格：人和仿真协作。人做方向选择，仿真做参数空间搜索。
```

> 注：此 SKILL 与深蓝的晶壳变化有直接关联——小说中晶壳的纹路变化可能是"晶格重组"的某种表现形式。

### 6.4 【信号降噪】Signal Denoising

| 属性 | 内容 |
|------|------|
| **门派** | 器宗 |
| **武侠类比** | 听声辨位——在嘈杂环境中分辨出目标声音 |
| **等级上限** | L3 |
| **适用场景** | 电磁干扰滤波、信号恢复、传感器数据清洗 |

**L1 场景描述**: 从含噪声的传感器信号或通信信号中提取有效信号，识别噪声模式（白噪声、工频干扰、脉冲噪声、串扰），选择合适的滤波器或信号处理方法恢复信号。

**L2 过程记录**: (1) 采集含噪信号样本；(2) 频谱分析，识别噪声频段；(3) 选择滤波方法（硬件滤波/软件滤波/自适应滤波）；(4) 参数调优；(5) 验证信噪比改善。

**L3 决策记录**:
- 关键决策点 1：滤波策略——"频域滤波（去除特定频率）"vs"时域滤波（滑动平均/中值）"vs"自适应滤波"
- 关键决策点 2：信号特征保留——"保留细节（弱滤波）"vs"保留趋势（强滤波）"
- 关键决策点 3：实时性要求——"在线滤波（低延迟）"vs"离线滤波（高精度）"

**L4 蒸馏知识**:
- 经验法则 1：噪声的频谱特征比幅度更重要——"知道噪声从哪来，比知道它多大更有用"
- 经验法则 2：信号降噪分两步——"先滤掉你能识别的噪声，再用统计方法处理剩余部分"
- 经验法则 3：不要过度滤波——"滤掉噪声的同时也滤掉了信号，就失去了测量的意义"
- 反模式：用单一滤波器处理所有场景

**L8 创造者印记**:
```
决策哲学：噪声不是你消除的，是你学会忽略的。
审美偏好：滤波后的信号曲线要平滑，但不能失真。
风险容忍度：中。允许信号有一定延迟，不允许信号失真。
协作风格：测试驱动。先跑标准信号验证滤波效果，再接入真实信号。
```

### 6.5 【机械手感】Tactile Mechanical Sense

| 属性 | 内容 |
|------|------|
| **门派** | 器宗 |
| **武侠类比** | 手法——手上功夫，靠的是触觉和肌肉记忆 |
| **等级上限** | L5（稀有，极难传承） |
| **适用场景** | 精密机械维修、手工装配、通过触觉诊断机械状态 |

**L1 场景描述**: 通过触觉（振动、阻力、温度、声音反馈）判断机械/电气设备的状态，在不依赖仪器的情况下识别异常——包括螺丝扭矩、轴承磨损、电机电刷火花、焊接质量、连接器插拔力。

**L2 过程记录**: (1) 手触设备表面，感受温度和振动基线；(2) 操作设备（转动/按压/插拔），感受阻力变化曲线；(3) 与记忆中的"正常手感"对比；(4) 定位偏差来源；(5) 修复后再次验证手感。

**L3 决策记录**:
- 关键决策点 1：判断基准——"和个人经验对比"vs"和标准值对比"
- 关键决策点 2：工具使用——"手是最好的工具"vs"用扭矩扳手验证直觉"
- 关键决策点 3：可重复性——"手感能否被传授"vs"只能自己积累"

**L4 蒸馏知识**:
- 经验法则 1：机器不舒服的时候会叫——"声音不对就是有问题"（来自父亲的智慧）
- 经验法则 2：拧螺丝的阻力不是线性的——"最后半圈的感觉最重要"
- 经验法则 3：手是最好的诊断工具——"仪器告诉你数据，手告诉你感觉"
- 反模式：过度依赖仪器判断，忽略手感信号

**L8 创造者印记**:
```
决策哲学：机器不舒服的时候会叫。你听不听得到，是你的问题。
审美偏好：亮的焊点是活的，灰的焊点是死的。活的焊点有光泽，有温度。
风险容忍度：中高。相信手感，但用量具验证。
协作风格：师徒制。只有一起做过，才知道"手感"是什么。
```

## 七、判断决策域 SKILL 详解

### 7.1 【共识锚定】Consensus Anchoring

| 属性 | 内容 |
|------|------|
| **门派** | 气宗 |
| **武侠类比** | 定心——在混乱中保持内心不动，引导方向 |
| **等级上限** | L4 |
| **适用场景** | 策元分歧调解、方向争议仲裁、共识形成引导 |

**L1 场景描述**: 在策元成员对方向、方案或评估产生分歧时，识别分歧的根源（事实分歧/价值观分歧/利益分歧），引导团队形成可执行的共识——不一定是所有人同意，而是所有人能接受的前进方向。

**L2 过程记录**: (1) 识别分歧类型——事实分歧（数据不够）vs 价值观分歧（优先级不同）vs 利益分歧（资源分配）；(2) 为事实分歧提供更多数据或模拟；(3) 为价值观分歧明确"不可妥协的底线"vs"可协商的偏好"；(4) 为利益分歧设计分配方案（轮流/抽签/按贡献比例）；(5) 记录共识锚点和未达成一致的部分。

**L3 决策记录**:
- 关键决策点 1：何时介入——"分歧刚出现时"vs"分歧僵持时"vs"分歧即将升级时"
- 关键决策点 2：介入方式——"提供选项"vs"提供框架"vs"直接建议"
- 关键决策点 3：共识标准——"所有人同意"vs"多数同意+少数保留"vs"足够前进即可"

**L4 蒸馏知识**:
- 经验法则 1：事实分歧最好解决——"给数据，分歧就消失了"
- 经验法则 2：价值观分歧不能解决，只能隔离——"明确底线，剩下的自由选择"
- 经验法则 3：共识不是"所有人都同意"——"共识是'虽然我不完全同意，但我可以接受往前走'"
- 反模式：用投票代替讨论（投票是共识的终点，不是起点）

**L8 创造者印记**:
```
决策哲学：共识不是消除分歧，是让分歧不妨碍前进。
审美偏好：共识锚点要清晰到每个人都能自己说出来。
风险容忍度：低。共识不能建立在模糊的"大家都没意见"上。
协作风格：倾听驱动。先听够所有人的立场，再说话。
```

### 7.2 【方向感知】Direction Sensing

| 属性 | 内容 |
|------|------|
| **门派** | 气宗 |
| **武侠类比** | 剑意——感知对手的剑意流向，预判下一招 |
| **等级上限** | L5（稀有） |
| **适用场景** | 创意图元的方向判断、趋势感知、涌现方向识别 |

**L1 场景描述**: 从超织体的创意图元池中感知涌现方向——哪些方向正在聚合、哪些方向在衰减、哪些方向即将进入活跃期。不依赖数据分析，而是通过"阅读"创意图元的 L8 印记和引用链模式来感知。

**L2 过程记录**: (1) 浏览创意图元池，不做选择，只是"看"；(2) 注意那些被引用链触感"粗糙"的图元；(3) 观察哪些方向的策元在形成、哪些在解散；(4) 记录"感觉"，但不立即做判断；(5) 过一段时间回看，验证直觉。

**L3 决策记录**:
- 关键决策点 1：何时相信直觉——"数据不足时"vs"数据矛盾时"vs"数据过多时"
- 关键决策点 2：方向选择——"跟随主流方向"vs"选择边缘方向"vs"等待更多信号"
- 关键决策点 3：何时要放弃——"方向衰减信号"vs"个人能力不匹配"vs"时机未到"

**L4 蒸馏知识**:
- 经验法则 1：方向不是"想出来的"，是"长出来的"——"你只能发现它，不能创造它"
- 经验法则 2：粗糙的引用链比光滑的更有价值——"有判断力印记的方向，值得跟"
- 经验法则 3：方向感知需要"空"——"塞满任务令的时候，感觉不到方向"
- 反模式：用数据分析完全替代直觉判断

**L8 创造者印记**:
```
决策哲学：方向不是选出来的，是感觉到的。感觉不到的时候，不要选。
审美偏好：粗糙的引用链比光滑的可靠。糙的是人写的，光滑的是AI生成的。
风险容忍度：高。允许选错方向，但要及时确认或放弃。
协作风格：独立。方向感知是个人的事。策元讨论是在感知之后，不在之前。
```

> 注：此 SKILL 与小说中"策元的眼睛"概念直接关联——林屿在 SKILL 市场中感知识别粗糙和光滑的引用链，正是"方向感知"的雏形。

### 7.3 【风险编织】Risk Weaving

| 属性 | 内容 |
|------|------|
| **门派** | 气宗 |
| **武侠类比** | 布网——编织一张风险评估的网，兜住所有可能的失败 |
| **等级上限** | L4 |
| **适用场景** | 方案评估、决策推演、风险收益分析 |

**L1 场景描述**: 将多维度风险信号（技术风险、协作风险、时间风险、市场风险）编织为综合风险评估，通过决策树推演不同选择的后果分布，辅助做出"可接受的失败"的选择。

**L2 过程记录**: (1) 列出所有备选方案；(2) 对每个方案，展开"最坏情况"推演——（技术失败、团队流失、市场变化）；(3) 评估每种失败的可恢复性和影响范围；(4) 比较"失败的代价"vs"成功的收益"；(5) 选择"可接受的失败落在自己身上"的方案。

**L3 决策记录**:
- 关键决策点 1：风险维度——"技术风险"vs"协作风险"vs"时间风险"——哪个最重要
- 关键决策点 2：时间范围——"3个月内的风险"vs"1年内的风险"vs"3年内的风险"
- 关键决策点 3：可接受性——"失败落在自己团队"vs"失败落在整个网络"——前者可接受

**L4 蒸馏知识**:
- 经验法则 1：两种失败——"可修复的失败"vs"不可逆的失败"——选前者
- 经验法则 2：失败落在自己团队比落在整个网络好——"自己扛得住，网络扛不住"
- 经验法则 3：风险不是概率，是分布——"不是'会不会发生'，是'发生了之后怎么办'"
- 反模式：追求"零风险"方案（没有零风险，只有不同风险的分布）

**L8 创造者印记**:
```
决策哲学：风险不可消除，只能选择。选择你扛得起的那个。
审美偏好：决策树要清晰到每个分支都有人负责。
风险容忍度：必须高。做风险编织的人，自己要能承受风险。
协作风格：透明。评估结果向所有人公开，不隐瞒最坏情况。
```

> 注：此 SKILL 在小说中已有对应——林屿在"方案A vs 方案B"的选择中，核心判断就是"可接受的失败落在自己身上"。

### 7.4 【判断力签名】Judgment Signature

| 属性 | 内容 |
|------|------|
| **门派** | 气宗 |
| **武侠类比** | 心法——将心法刻入每一招每一式 |
| **等级上限** | L5（稀有，不可复制） |
| **适用场景** | 填写 L8 创造者印记、形成个人判断力风格、在 SKILL 中留下"人"的痕迹 |

**L1 场景描述**: 在创建 SKILL 时，准确地在 L8 中表达个人的决策哲学、审美偏好、风险容忍度和协作风格——不是写"正确"的话，而是写"真实"的话。L8 的"真实"比"正确"更重要。

**L2 过程记录**: (1) 回顾自己在任务令中的关键决策；(2) 识别重复出现的判断模式；(3) 用具体的话表达这些模式——不是"做正确的事"这种废话，而是"能跑的代码不一定是好代码，能被别人读懂的才是"这种有取舍的话；(4) 判断：如果需要修改，只能 append 新版本，不能覆盖；(5) 提交。

**L3 决策记录**:
- 关键决策点 1：真实 vs 正确——"写真实但可能错的话"vs"写正确但空洞的话"
- 关键决策点 2：具体 vs 通用——"针对特定场景的经验"vs"放之四海皆准的原则"
- 关键决策点 3：现在 vs 未来——"现在的自己"vs"想成为的自己"

**L4 蒸馏知识**:
- 经验法则 1：L8 不是"写"出来的，是"长"出来的——"做够多的任务令，L8 自然就有了"
- 经验法则 2：L8 的矛盾是好的——"有矛盾说明是真实的，不是编的"
- 经验法则 3：L8 不可修改，但可以 append——"今天的你不需要否定昨天的你，只需要补充"
- 反模式：写"正确"但空洞的话（"做正确的事""追求卓越"——没有人会从这些话里读到任何东西）

**L8 创造者印记**:
```
决策哲学：L8 不是说给别人听的，是说给自己听的。写下来，你就知道自己是谁。
审美偏好：真实的矛盾比完美的统一更美。有矛盾，说明是活的。
风险容忍度：极高。L8 写下来就不可改了。你要接受——未来的你可能会觉得现在的你写得不对。
协作风格：对己。L8 是你和自己的对话。别人读到，是顺便的。
```

### 7.5 【涌现监测】Emergence Monitoring

| 属性 | 内容 |
|------|------|
| **门派** | 气宗 |

**L3 决策记录**:
- 关键决策点 1：异常阈值——"标准差法"vs"趋势突变点"vs"领域专家判断"
- 关键决策点 2：预警级别——"通知"vs"建议"vs"警报"

**L4 蒸馏知识**:
- 经验法则 1：涌现不是设计出来的，是监测出来的——"你只能发现它，不能控制它"
- 经验法则 2：结构突变比数值偏差更危险——"连接方式变了，才是真正的变化"
- 经验法则 3：健康的生态有"涟漪"——"太安静的系统，可能已经死了"
- 反模式：过度干预（监测的目的是知道，不是控制）

**L8 创造者印记**:
```
决策哲学：看整体，不看局部。一个策元的变化不重要，一百个策元的模式才重要。
审美偏好：涟漪。好的系统有涟漪——波动但不震荡，变化但不失控。
风险容忍度：中。允许局部波动，不允许系统性崩溃。
协作风格：广播。监测结果公开，不筛选，不过滤。
```

### 8.1 【场景映射】Scenario Mapping

| 属性 | 内容 |
|------|------|

| **武侠类比** | 移形换影——将一门武功的招式映射到另一门武功 |
| **等级上限** | L4 |
| **适用场景** | 跨领域知识迁移、模式识别、类比推理 |

**L1 场景描述**: 识别不同领域 SKILL 之间的结构相似性，将已验证的解决方案模式从一个领域映射到另一个领域——例如，将"数据管道编织"的模式映射到"能量流诊断"。

**L2 过程记录**: (1) 分析源领域 SKILL 的 L1-L4，提取其核心模式（抽象结构，非具体实现）；(2) 扫描目标领域的 SKILL 空间，寻找结构相似的问题；(3) 验证映射的可行性；(4) 创建桥接 SKILL 或直接 Fork；(5) 在目标领域测试和验证。

**L3 决策记录**:
- 关键决策点 1：抽象层次——"具体实现映射"vs"抽象模式映射"vs"元方法映射"
- 关键决策点 2：映射方向——"单向映射"vs"双向映射"vs"多向映射网络"
- 关键决策点 3：映射验证——"语义验证"vs"功能验证"vs"效果验证"

**L4 蒸馏知识**:
- 经验法则 1：跨域映射的成败取决于抽象层次——"太具体没有用，太抽象用不了"
- 经验法则 2：映射的中间表示要和两端都不同——"桥的中间不属于两岸"
- 经验法则 3：第一次跨域映射需要 3 倍时间——"不是因为难，是因为要建立新的连接"
- 反模式：强制映射（两个领域本质上不同，不要硬套）

**L8 创造者印记**:
```
决策哲学：模式是可迁移的，实现不是。学会看模式，不要背实现。
审美偏好：映射的中间表示要简洁。用最少的规则描述最多的场景。
风险容忍度：中高。允许映射失败，但保留回溯路径。
协作风格：跨域对话。和两个领域的人分别聊，才能找到映射点。
```

### 8.2 【策元之眼】Genesis Eye

| 属性 | 内容 |
|------|------|
| **门派** | 阵法 |
| **武侠类比** | 开天眼——看到常人看不到的"气" |
| **等级上限** | L5（稀有，与个人天赋相关） |
| **适用场景** | 感知引用链质量、识别 SKILL 的"生命力"、判断 SKILL 创建者的 Phronesis 水平 |

**L1 场景描述**: 通过阅读 SKILL 的 L8 和引用链，感知 SKILL 的"触感"——粗糙的引用链（有判断力印记）和光滑的引用链（缺少判断力印记）在触控板上的反馈不同。这种感知能力无法通过训练获得，部分依赖个人天赋。

**L2 过程记录**: (1) 在 SKILL 市场中用手指滑动浏览引用链；(2) 注意触觉反馈——粗糙（有判断力）vs 光滑（无判断力）；(3) 关注 L8 的"噪点"——真实的 L8 有像素颗粒随机偏移，AI 生成的 L8 过于平滑；(4) 记录哪些 SKILL 的"手感"好；(5) 回看这些 SKILL 的实际使用效果，验证感知。

**L3 决策记录**:
- 关键决策点 1：何时相信触感——"触感与数据一致时"vs"触感与数据矛盾时"
- 关键决策点 2：触感差异的来源——"L8 的内容质量"vs"引用链的深度"vs"某种未知因素"
- 关键决策点 3：如何验证——"跟踪使用效果"vs"与创造者交流"vs"等待更多数据"

**L4 蒸馏知识**:
- 经验法则 1：粗糙的结是活的——"有判断力印记的 SKILL，引用链的触感是粗糙的"
- 经验法则 2：光滑的结可能是 AI 生成的——"没有 Phronesis 痕迹的 SKILL，摸起来像玻璃"
- 经验法则 3：噪点密度代表判断力密度——"L8 的像素偏移越多，说明创造者思考得越多"
- 反模式：完全依赖触感（触感是信号，不是证据）

**L8 创造者印记**:
```
决策哲学：SKILL 就像一个表面。人写的和 AI 写的，摸起来不一样。
审美偏好：粗糙的比光滑的好。有纹理的是"长"出来的，没有纹理的是"造"出来的。
风险容忍度：高。允许判断错误，但要持续校准。
协作风格：感知后分享。自己先感受，再跟团队讨论。
```

> 注：此 SKILL 是小说中林屿的独特能力——超织体界面中引用链的"粗糙"和"光滑"触感。这是"策元的眼睛"的核心设定。

### 8.3 【异步协作】Async Collaboration

| 属性 | 内容 |
|------|------|
| **门派** | 阵法 |
| **武侠类比** | 分身术——一个人在不同时区同时工作 |
| **等级上限** | L3 |
| **适用场景** | 跨时区团队协作、异步文档审核、异步决策 |

**L1 场景描述**: 在跨时区的策元中建立高效异步协作模式——文档驱动沟通、异步决策、录制回放、离线缓存。目标是将"等待"从协作中消除。

**L2 过程记录**: (1) 建立文档驱动沟通（先写文档，再讨论）vs 会议驱动沟通（先开会，再记录）；(2) 设计异步决策流程（提案→评论→投票→结论）；(3) 配置异步工具（Matrix 频道、视频录制回放、CRDT 冲突解决）；(4) 设定响应时间期望（24 小时内回复）；(5) 定期同步（每周一次视频会议对齐）。

**L3 决策记录**:
- 关键决策点 1：同步 vs 异步——"紧急决策（同步）"vs"常规决策（异步）"
- 关键决策点 2：文档质量——"详细文档（减少沟通成本）"vs"简洁文档（减少阅读负担）"
- 关键决策点 3：工具选择——"成熟工具（稳定）"vs"新兴工具（效率高但不确定）"

**L4 蒸馏知识**:
- 经验法则 1：异步协作靠文档的质量——"文档写得好，会议就少"
- 经验法则 2：跨时区重叠的时间窗口很宝贵——"用于同步讨论，不用于状态同步"
- 经验法则 3：决策不要等所有人——"设定期限，期限内不回 = 同意"
- 反模式：用异步工具做同步沟通（如用文档聊天）

**L8 创造者印记**:
```
决策哲学：等待是协作最大的成本。消除等待，比消除分歧更重要。
审美偏好：文档要能独立阅读。不需要上下文，不需要额外解释。
风险容忍度：中。异步决策可能慢一点，但更完整。
协作风格：异步。写好文档，等人来读。不催。不追。
```

### 8.4 【Skill 蒸馏】Skill Distillation

| 属性 | 内容 |
|------|------|
| **门派** | 阵法 |
| **武侠类比** | 炼丹——从众多药材中提炼精华 |
| **等级上限** | L4 |
| **适用场景** | 从多个任务令中提炼通用 SKILL、做 SKILL 模板 |

**L1 场景描述**: 从多个相关任务令的执行记录中，提取共性模式，封装为可复用的 SKILL 模板——让下游策元不需要重复"从零摸索"的过程。

**L2 过程记录**: (1) 收集同一类型的多个任务令（≥5 个）；(2) 对比每个任务令的 L3 决策记录，找出共性决策点；(3) 将共性抽象为 L4 蒸馏知识；(4) 设计可参数化的 L5 代码模板；(5) 测试模板在不同策元中的适用性。

**L3 决策记录**:
- 关键决策点 1：提炼粒度——"细粒度（保留更多细节）"vs"粗粒度（覆盖更广场景）"
- 关键决策点 2：参数化程度——"少参数（简单但局限）"vs"多参数（灵活但复杂）"
- 关键决策点 3：通用性门槛——"覆盖 3 个场景即可发布"vs"覆盖 5 个场景再发布"

**L4 蒸馏知识**:
- 经验法则 1：SKILL 模板的价值在于减少了"判断"——"非通用参数越少，模板越好用"
- 经验法则 2：L4 是模板的核心——"代码可以抄，但经验不能抄"
- 经验法则 3：模板要有"离开路径"——"不用模板也能做，但用模板更快"
- 反模式：过度抽象（试图覆盖所有场景 = 覆盖不了任何场景）

**L8 创造者印记**:
```
决策哲学：好的模板不是"什么都考虑到了"，是"常见的不需要重新判断"。
审美偏好：简单。模板用起来不需要看文档，是最好的文档。
风险容忍度：中。允许模板在某些边缘场景失效，但核心场景必须可靠。
协作风格：开放。模板接受 PR，接受 fork，接受批评。
```

> 注：此 SKILL 与"酿造策元"的核心方向直接关联——"把经验变成可复用的东西"。

### 8.5 【蜂群感知】Swarm Sensing

| 属性 | 内容 |
|------|------|
| **门派** | 阵法 |
| **武侠类比** | 心念相通——不需要语言，彼此知道对方要做什么 |
| **等级上限** | L5（稀有，需要特定条件） |
| **适用场景** | 多 Agent 协作状态感知、涌现行为识别、集体智能协调 |

**L1 场景描述**: 感知多个 Agent 或智权体在协作中的涌现状态——谁在瓶颈、谁在等待、谁在空闲、谁在绕远路——不依赖明确的通信，而是通过观察行为模式来感知。

**L2 过程记录**: (1) 观察每个节点的行为模式（任务领用频率、执行时间分布、协作模式）；(2) 识别异常模式——"某人等待时间过长""某人任务堆积""某步骤重复执行"；(3) 推断涌现瓶颈；(4) 提出调整建议；(5) 观察调整后的涌现状态。

**L3 决策记录**:
- 关键决策点 1：干预时机——"立即干预"vs"观察一段时间"vs"由节点自修复"
- 关键决策点 2：干预方式——"直接调整"vs"提供建议"vs"改变环境条件"
- 关键决策点 3：感知粒度——"单节点粒度"vs"子图粒度"vs"全局粒度"

**L4 蒸馏知识**:
- 经验法则 1：涌现瓶颈不在最慢的节点，在最忙的节点——"瓶颈不是慢，是堵"
- 经验法则 2：蜂群不需要中央调度——"改变环境条件，比给每个节点发指令有效"

- 反模式：过度干预（蜂群的自组织能力比外部调度强）

**L8 创造者印记**:

| 组合 | SKILL 1 | SKILL 2 | 涌现效果 | 适用场景 |
|:----:|---------|---------|---------|---------|
| **编年** | 数据管道编织 | 引用链溯源 | 自动追踪数据来源的引用链，给每个数据打上"可信度"标签 | 数据溯源审计 |
| **诊脉** | 传感器校准术 | 能量流诊断 | 从传感器信号异常直接定位到能量流瓶颈 | 硬件故障排查 |

| **鉴真** | 引用链溯源 | 策元之眼 | 触感+数据双通道验证 SKILL 真伪 | 方舟假 L8 识别 |
| **传承** | Skill 蒸馏 | L8 真言 | 在提炼通用 SKILL 时保留原始创造者的判断力印记 | 酿造策元做模板 |
| **涌现** | 涌现监测 | 蜂群感知 | 从宏观和微观两个层面感知系统状态 | 生态危机预警 |

| **通灵** | 深蓝协议 | 晶格重组 | 深蓝晶壳变化与材料制造参数联动 | 生物制造 |
