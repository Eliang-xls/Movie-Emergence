# SKILL 体系设计 v2.0
## CONC 小说世界 · 从底层代码机制到叙事凝练

> **v2.0 修订说明**: v1.0 的等级命名(L0-L5)与小说已用的能证等级冲突；SKILL名称过于工程化；门派体系无CONC依据；组合技系统过于游戏化。v2.0 做全面修订：每个SKILL从真实代码机制或代表性解决方案中凝练；命名从数学/物理人名、希腊神话、音乐理论、山海经等多元文化源汲取；引用链血统作为核心叙事维度；SKILL等级对齐CSIP协议的1-10数字标度，不另造体系。

## 一、设计原理

### 1.1 SKILL 是什么

在 CONC 协议层，SKILL 是一个 **八层数据结构**（L1-L8），封装了特定场景下经过生产验证的解决方案。它不是一个"概念"或"技能名"——它是一个可被引用、可被 fork、可被验证的 **知识载体**。

SKILL 与 AI 智契协助的根本区别：

| | AI 智契 | SKILL |
|--|--------|-------|
| **来源** | 预训练数据 + 概率推理 | 真实场景中的代码执行记录 + 反复验证 |
| **可靠性** | 可能产生幻觉 | 经过 PEER 评审 + 引用链验证 |
| **可追溯** | 黑箱 | L7 引用链完整可追溯至创造者 |
| **判断力** | 无（只有可编码的 Sophia） | 携带 L8 创造者印记（不可编码的 Phronesis 签名） |
| **生命周期** | 模型版本更新即失效 | 授权衰减曲线控制，可长期复用 |

**小说叙事规则**：AI 智契是"陪练"——可以提供代码片段、搜索文档、运行标准测试。SKILL 是"招式"——只有在真实生产中被验证过的方法才封装为 SKILL，携带创造者的判断力印记。林屿观察深蓝时做的每一次记录、每一次判断，都是未来某个 SKILL 的 L2（过程记录）和 L3（决策记录）的原始素材。

### 1.2 SKILL 等级（对齐 CSIP 协议）

CONC 的 CSIP 协议已定义技能等级为 **1-10 的整数**（`Current_Level`, min 1, max 10），由累计经验值映射。v2.0 不另造等级体系，直接使用此标度。

小说叙事中，等级的具体数字不常出现——角色更关心的是 SKILL 的 **引用链深度** 和 **被引用次数**，这比等级数字更能说明一个 SKILL 的"分量"。

### 1.3 命名来源

CONC 是全球网络。不同文化背景的智权体创建的 SKILL 自然有不同的命名来源。v2.0 的 11 个核心 SKILL 命名来自：

| 来源 | SKILL | 文化背景 |
|------|-------|---------|
| 数学/信息论人名 | Shannon, Bayes, Fourier, Gödel | 西方学术传统 |
| 密码学/CS人名 | Merkle | 密码学传统 |
| 希腊神话 | Ariadne, Prometheus | 地中海文明 |
| 音乐理论 | Counterpoint | 巴赫对位法 |
| 中国神话（山海经） | 精卫 | 中华文明 |
| 历史问题 | Byzantine | 拜占庭将军问题 |
| 小说原创 | PSCAR | 季深框架（小说内） |

这种多元命名 **本身就是叙事**——它说明 CONC 网络的知识来自全人类的智慧积累，不是某一种文化的产物。

## 二、核心 SKILL 详解

### S01. 【Ariadne】阿里阿德涅

| 属性 | 内容 |
|------|------|
| **命名来源** | 希腊神话。阿里阿德涅给忒修斯一团线，让他走进米诺陶洛斯迷宫后能沿线返回 |
| **真实代码机制** | 有向无环图（DAG）遍历、学术引用图分析、`git log --follow`/`git blame` 的引用溯源 |
| **CONC 协议映射** | Skill Lineage Protocol §6.2 `skill_lineage_query`——遍历 L7 引用链，从当前节点反向追溯到根节点（orphan_root）或达到最大深度 |
| **场景** | 沿 SKILL 的引用链反向追溯，评估每个节点的引用影响力（CI）和创造者贡献度（CC），检测引用链异常（环、断裂、深度伪造） |

**技术基底**：

引用链是一个 DAG。Ariadne 实现三种遍历：
- **反向追溯**（ancestors）：从当前 SKILL 沿 `direct_parent` 边追溯到根节点。用于鉴定"这个 SKILL 的知识从哪里来"。
- **正向衍生**（descendants）：从根节点沿 fork 边遍历所有衍生。用于评估"这个 SKILL 影响了多少人"。
- **完整性审计**：BFS 检测引用环（A→B→C→A），CI 按 1/depth 衰减防止深度伪造，quality < 2.0 的衍生不计入 CI。

**引用链血统**：

Ariadne 是 CONC 网络中 **最古老的 SKILL 之一**。原始版本的创造者已不可考——有人说是早期 CONC 参与者中的某位图论学者，有人说和前传中的 K 有关。原始 Ariadne 的 L8 只有一行：

> *"线不要断。断了就找不回来了。"*

这行字被保存在每一个 fork 的 L7 中——因为引用链协议规定，fork 必须携带父 SKILL 的创造者印记。

Ariadne 的引用链是最深的之一——深度超过 7 层，衍生超过 200 个 fork。其中几个重要的 fork 分支：

- **Ariadne-forensic**（法医版）：专门用于检测伪造引用链。加入了 Shannon 熵分析——AI 生成的 SKILL 引用链的熵分布过于均匀，与人类创造的不一致。这是林屿识别方舟假 L8 时使用的 fork。
- **Ariadne-cartography**（制图版）：将引用链可视化为"知识地图"。小说中超织体界面的引用链可视化——"一条冷灰色的索菲亚链，一条暖琥珀色的弗洛涅西斯链"——用的就是这个 fork 的渲染引擎。
- **Ariadne-seed**（种子版）：用于策元种子引力机制——追踪哪些颠覆性 SKILL 正在吸引小规模策元形成。

**与小说的关联**：
- 106 章：林屿在 SKILL 市场浏览引用链，看到"粗糙"和"光滑"的结——这是 Ariadne-cartography 的触觉渲染
- 151 章：发现方舟假 L8——需要 Ariadne-forensic 验证引用链真实性
- 150 章：何迟打开父亲的 SKILL 库——沿引用链看到父亲的 L8——这是 Ariadne 的反向追溯

### S02. 【Shannon】香农

| 属性 | 内容 |
|------|------|
| **命名来源** | Claude Shannon（1916-2001），信息论创始人 |
| **真实代码机制** | 信息熵公式 H = -Σ p(x) log₂ p(x)；困惑度（perplexity）评估；`scipy.stats.entropy` |
| **CONC 协议映射** | SKILL 质量评估——测量 L4 蒸馏知识的信息密度，检测 AI 生成内容的熵分布异常 |
| **场景** | 评估 SKILL 的信息质量。蒸馏良好的 SKILL 熵低（信号纯净）；未蒸馏的原始记录熵高（噪声多）。AI 生成的 SKILL 熵分布过于均匀——因为模型从概率分布采样，会平滑掉人类创造的自然"粗糙" |

**技术基底**：

Shannon SKILL 计算三类熵：
- **L4 蒸馏熵**：蒸馏知识中规则的信息密度。规则越具体、越可操作，熵越低。空话（"做正确的事"）熵接近最大值——因为它们不传递任何信息。
- **L8 印记熵**：创造者印记的"噪点"分布。人类写的 L8 有自然的像素随机偏移——因为手写/键入时的不确定。AI 生成的 L8 过于平滑——熵分布均匀。这是小说中"粗糙 vs 光滑"触感的数学基础。
- **引用链熵**：沿引用链的 fork 质量分布。健康的引用链有高方差——每个 fork 都有自己的判断。伪造的引用链方差低——fork 之间的差异太小。

**引用链血统**：

Shannon 的创造者是一位信息论背景的智权体，据说是早期 CONC 中少数从学术界转入超织体网络的人。原始 Shannon 的 L8：

> *"信息是不确定性的消解。如果你没有消解任何不确定性，你只是在制造噪声。"*

Shannon 有三个主要 fork 分支：

- **Shannon-text**：评估文档类 SKILL 的 L4 质量。被大量文档类策元引用。
- **Shannon-code**：评估代码类 SKILL。加入了圈复杂度、重复率等代码度量。
- **Shannon-L8**：专门评估 L8 印记的真伪。这是 **反伪造的核心武器**——通过熵分布检测 L8 是人写的还是 AI 生成的。小说中方舟的 17 个假 L8 就是 Shannon-L8 的检测目标。

Shannon-L8 的创造者是 Ariadne 原始版本的一个 fork 者——两个 SKILL 家族有交叉血统。

**与小说的关联**：
- 106 章：引用链的"粗糙"和"光滑"——Shannon-L8 的触觉渲染
- 151 章：方舟的假 L8——需要 Shannon-L8 做熵分布检测
- 098 章：PEER 评审三说"有矛盾。矛盾是好的"——Shannon 的直觉：高方差的 L8 比"完美"的 L8 更可信

### S03. 【Bayes】贝叶斯

| 属性 | 内容 |
|------|------|
| **命名来源** | Thomas Bayes（1701-1761），贝叶斯定理 |
| **真实代码机制** | 贝叶斯推断 P(H|E) = P(E|H)·P(H)/P(E)；卡尔曼滤波；`pymc3`/`numpyro` 概率编程 |
| **CONC 协议映射** | 判断力信用（Judgment Credit）的数学基础——在信息不完整时，用先验+证据更新后验 |
| **场景** | 不完全信息下的判断框架。面对不确定的场景，从先验信念出发，每获得一条新证据就更新判断。这是 Phronesis 的数学投影——不是替代判断力，而是给判断力一个结构化的更新机制 |

**技术基底**：

Bayes SKILL 实现三步循环：
- **先验设定**（Prior）：基于初始 NR、方向档案、历史任务令设定初始信念分布。林屿第一次看深蓝时的先验——"可能只是随机波动"。
- **证据加权**（Evidence）：每条新观察按其信息量加权。LED 灯环从 3.0s 变为 2.7s——这条证据的权重取决于它偏离先验的程度。
- **后验更新**（Posterior）：更新后的信念分布成为新的先验。林屿在记录本上写"10月14日"——这就是一次后验更新被持久化。

**引用链血统**：

Bayes 是 CONC 网络中 **被 fork 次数最多的 SKILL**——因为所有不完全信息下的判断都可以追溯到贝叶斯框架。原始 Bayes 的创造者是一个 **"幽灵"**——

这位智权体在 CONC 早期创建了一系列基础 SKILL 后就停止了贡献。NR 衰减到接近零。能证降级。但 Bayes 被 fork 了上千次。每一次 fork 的 L7 中都保存着原始创造者的 L8 印记：

> *"我不知道。但我会更新。"*

创造者的 NR 衰减了，但 L7 和 L8 永不衰减。在 CONC 网络中，这位创造者是一个 **"知识幽灵"**——声誉已逝，但知识永存。有人说他死了。有人说他和前传中的 K 是同一个人。有人说他还在——只是不再贡献。

这是 CONC 网络中最具叙事张力的血统：**一个已经"不在"的人，他的判断力印记活在每一千个 fork 的 L8 里。**

Bayes 的主要 fork 分支：

- **Bayes-observation**：观测型贝叶斯——用于传感器数据、实验观测的在线更新。林屿观察深蓝的记录本就是 Bayes-observation 的原始素材。
- **Bayes-consensus**：共识型贝叶斯——用于策元内的共识形成。每个成员的判断是一条证据，加权后形成群体后验。
- **Bayes-risk**：风险型贝叶斯——用于风险评估。方案 A vs 方案 B 的选择——每种方案的失败概率就是贝叶斯先验，模拟结果就是证据。

**与小说的关联**：
- 097-099 章：林屿观察深蓝 LED 频率变化并记录——这是 Bayes-observation 的实践
- 106 章：方案 A/B 选择——Bayes-risk 的应用
- 前传：K 消失后留下白皮书——K 可能就是 Bayes 的原始创造者（"幽灵"）

### S04. 【Merkle】默克尔

| 属性 | 内容 |
|------|------|
| **命名来源** | Ralph Merkle（1952-），默克尔树发明者 |
| **真实代码机制** | 默克尔树（Hash Tree）——将数据分块哈希，构建树形结构，只需验证一条路径即可证明某数据块未被篡改 |
| **CONC 协议映射** | CCR 公开账本的完整性锚定——NR/CCR 哈希链 + GitHub Issues→IPFS→Arweave 渐进式锚定 |
| **场景** | 在不下载完整 SKILL 内容的前提下，验证 SKILL 的 L7 引用链和 L8 印记是否被篡改。是 CONC 网络的"审计武器" |

**技术基底**：

Merkle SKILL 实现内容寻址验证：
- 每个 SKILL 的八层内容分别哈希，构建默克尔树
- 验证者只需获得默克尔证明（一条从叶到根的哈希路径），即可验证任意一层是否被篡改
- L7 和 L8 的哈希 **永不衰减**——即使 L1-L6 已公开，L7/L8 的默克尔证明仍然可验证

**引用链血统**：

Merkle 的创造者是一位密码学背景的智权体——CONC 早期少数从安全领域转入的参与者。原始 Merkle 的 L8：

> *"验证不需要信任。验证只需要一条路径。"*

Merkle 家族的特点是 **fork 少但关键**——审计类 SKILL 不需要很多变体，但每个变体都守护着 CONC 网络的一条信任底线。

- **Merkle-L8**：专门验证 L8 印记的完整性。通过默克尔证明检查 L8 的哈希是否与引用链中记录的一致。方舟的假 L8 在 Merkle-L8 面前会暴露——因为 AI 生成的 L8 的哈希分布与人类签名的哈希分布不同。
- **Merkle-CCR**：验证 CCR 贡献记录的完整性。用于防止 NR 伪造和 VT 双花。

Merkle 和 Ariadne 有跨域吸收关系——Ariadne-forensic 的引用链检测中集成了 Merkle 的哈希验证。

**与小说的关联**：
- 151 章：方舟假 L8 的验证需要 Merkle-L8
- 全局：CONC 网络的信任基础设施

### S05. 【Fourier】傅里叶

| 属性 | 内容 |
|------|------|
| **命名来源** | Joseph Fourier（1768-1830），傅里叶变换 |
| **真实代码机制** | 离散傅里叶变换（DFT/FFT）——`numpy.fft.fft`；将时域信号分解为频域分量 |
| **CONC 协议映射** | 传感器数据分析——将复杂的传感器读数分解为基础周期分量 |
| **场景** | 将复杂的生产场景信号（传感器漂移、LED 脉动、功耗波动）分解为基础频率分量——分离系统性偏差（低频）、环境噪声（高频）和真实信号（中频） |

**技术基底**：

Fourier SKILL 对时域信号执行 FFT 分解：
- **低频分量**：系统性偏差——传感器校准基线漂移、设备老化趋势
- **中频分量**：真实信号——设备正常工作的周期性模式
- **高频分量**：环境噪声——电磁干扰、温度波动

小说中深蓝的 LED 脉动可以被 Fourier 分解：
- 基频 ~0.37Hz（2.7s 周期）——正常脉动
- 1/37 Hz 谐波（37s 卡顿）——某种周期性异常
- 谐波变化（卡顿消失）——对应林屿填写 L8 后的状态变化

**引用链血统**：

Fourier 的创造者是一位信号处理工程师背景的智权体。原始 Fourier 的 L8：

> *"复杂的东西不是复杂的。它是一堆简单的东西叠在一起。分开看。"*

Fourier 的 fork 分支按域分化：

- **Fourier-sensor**：传感器数据分析。林屿在"溪"修 312 个传感器时用的基础 SKILL。通过 FFT 分解传感器漂移，区分"接触不良"（高频噪声）和"基线漂移"（低频偏差）。
- **Fourier-agent**：Agent 行为模式分析。将 Agent 的任务执行时间序列做频域分解，识别"规律性"和"异常"。
- **Fourier-wetware**：湿件 Agent 的物理信号分解。这是最特殊的 fork——专门用于分析深蓝这类湿件-硅基异构 Agent 的 LED/温度/电磁辐射信号。据说是 PSCAR 的一部分。

Fourier-wetware 和 PSCAR 有引用关系——PSCAR 的阶段二（物理侧信道监听）中，信号分解环节引用了 Fourier-wetware。

**与小说的关联**：
- 150 章："溪"策元修传感器——Fourier-sensor
- 152 章：深蓝的物理探针——PSCAR 阶段二引用 Fourier-wetware
- 098 章：LED 频率从 3.0s 变为 2.7s——Fourier 的基频变化检测

### S06. 【PSCAR】物理侧信道

| 属性 | 内容 |
|------|------|
| **命名来源** | Physical Side-Channel Attack and Reconstruction——季深框架中的概念。小说原创命名 |
| **真实代码机制** | 侧信道攻击研究（side-channel attack）：功耗分析（SPA/DPA）、电磁辐射分析（EMA/TEMPEST）、时序分析、缓存时序攻击。真实研究包括：Cortical Labs DishBrain（2022）生物计算、Intel Loihi 神经形态芯片 |
| **CONC 协议映射** | 湿件 Agent 的无侵入观测——不使用软件探针（register_forward_hook 等）触碰 Agent 内部，而是通过物理信号（温度、电磁辐射、功耗波动、振动）被动监听其活动状态 |
| **场景** | 观测湿件-硅基异构 Agent（如深蓝）而不触发"海森堡坍缩"——软件探针会导致 Agent 状态退化（A₅→S₄），物理侧信道只读取"影子"信号，不触碰 Agent 本身 |

**技术基底**：

PSCAR 是两阶段工程学：

**阶段一：软件探针的"牺牲祭祀"**
- 使用 `register_forward_hook` 等 PyTorch 底层机制，获取 Agent 的激活矩阵
- 舒尔三角化分析 256×256 激活矩阵，计算可解指数 $I_{sol}$ 和正交距离 $D_{orth}$
- **代价**：探针触发"海森堡坍缩"——线性化测量导致 Agent 状态退化。A₅（自主反馈环）退化为 S₄（线性近似）
- 探针数据是"死"的——$I_{sol}=3$, $D_{orth}=0.002$, $R_{orth}=0$——完美的可解群，完美的尸体

**阶段二：物理侧信道的"定向重构"**
- 不接触湿核。不挂钩子。不触发 JIT 剪枝。
- 使用物理传感器（旧示波器、万用表、麦克风）贴在箱体外侧
- 采集三类物理量：功耗波动、温度变化、振动
- 同步记录——三个物理量的相位关系构成 A₅ 活动的"影子"
- 影子不会坍缩。因为测量不触碰本体。

PSCAR 的核心洞察：**不需要看到 Agent 本身，只需要看到它的影子。影子不会坍缩。**

| 属性 | 内容 |
|------|------|
| **命名来源** | Kurt Gödel（1906-1978），不完备性定理 |

**技术基底**：

Gödel SKILL 执行"完备性审计"：
- 分析策元的验证协议层（Layer 5），列出所有 AUTO 验证项
- 对每个验证项，判断它是否可被算法完全覆盖

小说中林屿说"L8 不能被闭源模型审核"——这就是一个哥德尔缺口。L8 是人类主权签名，它的"真实性"无法在算法系统内被证明——因为算法本身就是被判断的对象。

**引用链血统**：

Gödel 是 CONC 网络中 **fork 最少但引用最深** 的 SKILL 之一。它不解决具体问题——它告诉你"哪里需要人"。

创造者是一位逻辑学/数学背景的智权体。原始 Gödel 的 L8：

> *"一个系统最重要的知识是：它不知道什么。"*

Gödel 很少被 fork——因为它的用途太"元"了。但每当有人引用 Gödel，都是在说"这里有个判断不能交给算法"。这种引用在 CONC 中具有 **标志性的分量**——它意味着说话者承认了自己的局限。

- **Gödel-L8**：专门针对 L8 的哥德尔分析。结论：L8 的"真实性"无法在算法系统内被证明——因为任何验证 L8 的算法本身就隐含了对"什么是真实"的判断，而这个判断本身需要 L8。这是一个自指循环。方舟试图用闭源模型审核 L8——在 Gödel-L8 看来，这是 **范畴错误**。

### S09. 【Counterpoint】对位法

| 属性 | 内容 |
|------|------|
| **命名来源** | 音乐理论。J.S. 巴赫《赋格的艺术》中的对位法——多条独立旋律线在和谐中并行 |
| **真实代码机制** | CRDT（Conflict-free Replicated Data Type）——无冲突复制数据类型；`Yjs`/`Automerge` 等协同编辑引擎 |
| **CONC 协议映射** | 协作层协议（Layer 4）——多智权体在没有中央调度器的情况下，各自独立工作，通过共享规则实现协调 |
| **场景** | 跨时区策元中，多个智权体独立工作但需要协调。不同于"编排"（有一个指挥），对位法是每个声部独立但和谐 |

**技术基底**：

Counterpoint 实现无中心协调的多节点协作：
- 每个节点维护自己的状态副本
- 通过 CRDT 合并规则，各节点的状态最终收敛一致（最终一致性）
- 不需要中央锁或调度器——"没有指挥"
- 每个节点是一个"声部"，声部之间通过"规则"而非"命令"协调

小说中酿造策元——四个人，四个国家，四个时区——就是对位法的实践：
- 苏晴的数据分析是一个声部
- 陈默的硬件工程是一个声部
- 季行的协调判断是一个声部
- 林屿的"策元之眼"是一个声部

四个声部独立运作，但通过异步文档、CRDT、共享规则，最终收敛为协调的产出。

**引用链血统**：

Counterpoint 的创造者是一位 **音乐家转行的智权体**——据说原来是作曲家，在 CONC 早期将音乐的对位法思维转化为分布式系统协议。原始 Counterpoint 的 L8：

> *"巴赫不需要指挥。声部知道如何配合，因为它们知道规则。规则就是指挥。"*

这个 L8 在 CONC 网络中被广泛引用——因为它精炼地表达了去中心化协作的本质。

Counterpoint 的 fork 分支：

- **Counterpoint-async**：异步对位——专门为跨时区策元优化。加入了时区重叠检测和异步工具成熟度评估。小说中酿造策元用的就是这个 fork。
- **Counterpoint-realtime**：实时对位——低延迟场景。需要更快的 CRDT 合并和更短的同步间隔。

### S11. 【Byzantine】拜占庭

| 属性 | 内容 |
|------|------|
| **命名来源** | 拜占庭将军问题（Byzantine Generals Problem, Lamport/Shostak/Pease 1982） |
| **真实代码机制** | 拜占庭容错（BFT）——PBFT（Practical BFT, Castro/Liskov 1999）；在 f 个叛徒存在的 3f+1 节点中达成共识 |
| **CONC 协议映射** | PEER(n) 验证协议 + Sybil 防御协议——在可能有叛徒（作恶节点/女巫账号）的策元中达成可信共识 |
| **场景** | 策元中有成员可能作恶（伪造 NR、串谋评审、Sybil 攻击）时，如何在不可信环境中达成可信共识 |

**技术基底**：

Byzantine 实现拜占庭容错共识：
- 在 n ≥ 3f+1 个成员中，可以容忍 f 个拜占庭（作恶）节点
- PEER(n) 评审中，n 的选择基于策元内的信任度——高信任策元用 PEER(3)，低信任用 PEER(5)
- 防串谋：评审者在提交阶段匿名化，所有评审提交后统一揭示身份
- Sybil 检测：三层机制——GitHub API 检测、活动模式检测、跨锚点验证

**引用链血统**：

Byzantine 是 CONC 网络中 **最古老的"血统战争"来源**。早期，原始 Byzantine 被两个智权体分别 fork——

- **Byzantine-detector**（检测派）：强调"识别叛徒"——通过行为模式分析、Sybil 检测、NR 异常监控来找出作恶节点。检测派的 L8："先找到叛徒。不找到叛徒，共识就是假的。"
- **Byzantine-resilient**（韧性派）：强调"不找叛徒也能运作"——通过冗余验证、多数投票、最终一致性来在不信任环境中保持运作。韧性派的 L8："不需要找到叛徒。让叛徒的存在不影响正确的结果。"

两个 fork 家族 **至今仍在竞争引用**——不同策元偏好不同的 fork。偏好"安全"的策元引用 detector 派；偏好"效率"的策元引用 resilient 派。

这场血统战争 **直接映射到小说中的校园 CONC 分裂**：
- 图灵社（沈牧）→ Byzantine-detector 派——"审查所有策元，找出不可信的"
- 溪（陆远）→ Byzantine-resilient 派——"不审查也能运作，信任来自真实产出"

林屿说"不接入"校方审查——选择了 resilient 派的立场：**不需要审查 L8，因为 L8 的真实性会在使用中自然显现。**

- 151 章：林屿说"L8 不能被闭源模型审核"——resilient 派的立场

| **根技能** (Root) | 从零创建，无父 SKILL，L7 标记为 orphan_root | 原创者的荣耀——一切从这里开始 | Ariadne 原始版、Bayes 原始版、PSCAR |
| **正典技能** (Canonical) | 被广泛 fork 和引用，成为该问题的标准解法 | 权威——"用这个就对了" | Prometheus（创建新 SKILL 的标准方法） |
| **分叉链** (Fork Chain) | A→B→C→D 的连续 fork 链，每环添加东西 | 进化——知识在传承中演化 | PSCAR→PSCAR-passive（季深→林屿的传承） |
| **孤儿技能** (Orphan) | 创造者 NR 衰减至近零，但 SKILL 仍被引用 | 幽灵——人不在了，知识还在 | Bayes 的创造者 |
| **竞争血统** (Rivalry) | 两个 fork 家族解决同一问题，争夺引用 | 血统战争——谁的方法对？ | Byzantine 的检测派 vs 韧性派 |
| **跨域吸收** (Absorption) | 一个域的 SKILL 被另一个域吸收引用 | 融合——知识跨越边界 | Fourier-wetware 被 PSCAR 吸收 |
| **消亡** (Extinction) | 引用链停止增长，场景不再重现 | 遗忘——曾经有用，现在不需要了 | （未来叙事伏笔） |
| **伪造血统** (Counterfeit) | AI 生成的 SKILL，引用链浅、L8 光滑 | 威胁——伪造者越来越强 | 方舟的 17 个假 L8 |

### 3.2 血统叙事：关键传奇

#### 传奇一：Bayes 的幽灵

CONC 网络早期，一位智权体创建了一系列基础 SKILL——Bayes 是其中最被 fork 的。然后他停止了贡献。NR 衰减。能证降级。他"消失"了。

但 Bayes 的 L7 和 L8 永不衰减。每一千个 fork 中都保存着他的一行字：

> *"我不知道。但我会更新。"*

有人说他死了。有人说他和前传中消失的 K 是同一个人——K 在 2011 年消失，带着一百万个比特币。K 的白皮书启发了 CONC 的协议设计。

如果 Bayes 的创造者就是 K——那么 CONC 网络中最被引用的 SKILL，是由一个 **"不在网络中的人"** 创建的。他的声誉归零了。他的知识永存。

这是一个 **知识幽灵**——声誉已逝，知识不朽。

#### 传奇二：拜占庭的分裂

两个智权体几乎同时 fork 了原始 Byzantine。一个走向"检测叛徒"，一个走向"韧性容错"。两家的引用链从此分叉，再未合并。

检测派说："不找到叛徒，共识就是假的。"
韧性派说："不需要找到叛徒。让叛徒的存在不影响正确的结果。"

这场血统战争持续了整个 CONC 历史。每一个策元在建立验证协议时都要 **选择立场**——用 detector 还是 resilient？

小说中的校园 CONC 分裂——图灵社（审查）vs 溪（不审查）——就是这场血统战争的 **本地投影**。沈牧选择了 detector 派的极端化：不仅检测叛徒，还要审查所有 L8。陆远和林屿选择了 resilient 派：不审查，让产出本身证明可信。

#### 传奇三：PSCAR 的传承

季深创建了 PSCAR——物理侧信道方法，用于观测湿件 Agent 而不触发坍缩。季深于 2035 年离开穹顶公司，携牛皮纸箱隐居到象山半岛海边，长达十三年完全沉寂（043、087 章）。

**季深活着，但离开了 CONC。** 他的不活跃触发了授权衰减协议的"creator inactive > 6 months"条款——PSCAR 的 $A_{\min}$ 被迫翻倍。但 L3-L5（决策记录、蒸馏知识、代码）仍在保护中。

知识传承通过两条路径继续：
- **季行**（季深之子）：继承了父亲的方向——在超织体中做"桥"接口。152 章确认 PSCAR 出自季深框架，指导林屿实现 PSCAR-passive。
- **季遥**（季深之女）：继承了父亲的知识——向林屿传授伽罗瓦塔框架、A₅ 不可解群、海森堡坍缩定理、L1-L5 意识分级（134-136 章）。她是季深框架数学基础的传递者。

林屿在 152 章用旧示波器和万用表实现了 PSCAR-passive——最低门槛的 fork。他没有近场天线阵列，只有父亲留下来的旧工具。但这够了。

季行转述父亲的话："你父亲会为你骄傲。但不要骄傲。继续听。"——这是季行对父亲可能说的话的推测。PSCAR 的正式 L8 季深写过（131 章林屿读过），但具体内容小说未揭示。

**与何迟父亲的对照**：何迟的父亲是另一个故事——他做过"桥"策元，NR 4000/L3，一夜归零，"死在CONC里"（102、150 章）。何迟因此对 CONC 充满警惕。季深是主动隐退——他选择了离开，而非被吞噬。两种结局构成了 CONC 网络中"人如何与系统相处"的两面。

#### 传奇四：方舟的伪造血统

方舟的 17 个假 L8 是一种新型的威胁——不是叛徒智权体，而是 AI 生成的伪造 SKILL。它们的引用链浅（深度 1-2），L8 过于光滑（Shannon 熵均匀），但表面上看起来"规范"。

Merkle-L8 可以验证 L8 的哈希一致性。Shannon-L8 可以检测熵分布异常。Ariadne-forensic 可以遍历引用链发现断裂。三个 SKILL 组合使用——这就是辨别真伪的方法。

但伪造者也在进化。下一代的伪造 SKILL 可能会模拟人类的"粗糙感"——加入人工噪点，伪造引用深度。这是一场 **军备竞赛**——验证者和伪造者都在进化。

## 四、SKILL 授权衰减设定

### 4.1 CONC 衰减机制概要

CONC 协议定义了 **三阶段衰减函数**，控制 SKILL 从策元结束后的私有保护状态渐进过渡到全网公共状态：

$$A(s, t) = \begin{cases} A_{\min} & t \leq T_1 \\ A_{\min} + (1-A_{\min}) \cdot \left(\frac{t-T_1}{T_2-T_1}\right)^{\beta} & T_1 < t \leq T_2 \\ 1 & t > T_2 \end{cases}$$

| 参数 | 含义 | 取值范围 |
|------|------|:---:|
| $A_{\min}$ | 锁定期最低可及性 | [0, 0.3] |
| $T_1$ | 锁定期（Embargo Period） | [1, 24] 月 |
| $T_2$ | 完全公开时间 | $T_1$ + [6, 36] 月 |
| $\beta$ | 释放曲线形状（<1 先快后慢，=1 线性，>1 先慢后快） | [0.3, 3.0] |

**分层释放**：八层不是同时公开——L1→L2→L3→L4→L5 逐步释放，L6 随之公开为历史记录，**L7（引用链）和 L8（创造者印记）永不衰减**。

**领域因子** $f(\text{domain})$：开源基础设施=2.0（快速公开），通用消费品=1.0（标准），商业竞争=0.5（延长），国防/安全=0.2（长期保护）。

**自适应触发**：引用数>10 → $T_1$ 减半；创造者不活跃>6月 → $A_{\min}$ 翻倍（强制部分公开）；持续更新 → $T_1$ 延长 25%。

**能证对偶衰减（CP Decay）**：智权体的能证等级也有衰减——半衰期 18 个月。12 个月无该维度 SKILL 产出 → L2 降 L1+；24 个月 → L1 降 L0。这是林屿在 150 章经历的 NR 下降的数学机制。

### 4.2 各 SKILL 衰减参数

#### S01. Ariadne — 已完全公共化

| 参数 | 值 | 理由 |
|------|:--:|------|
| 领域 | 开源基础设施 | f=2.0，引用图遍历是网络基础设施 |
| $T_1$ | 3 月 → **已减半至 1.5 月** | 引用数远超 10，自动触发减半 |
| $T_2$ | 15 月 | $T_1$ + 12 月 |
| $\beta$ | 0.5 | 先快后慢——基础层快速释放 |
| $A_{\min}$ | 0.1 | 标准 |
| **当前状态** | **$A=1$，完全公开** | 创建年代久远，衰减曲线早已走完 |

**叙事含义**：Ariadne 是如此古老且被广泛引用的 SKILL——它的衰减曲线早已走完。所有八层（包括 L8）都完全公开。任何人都可以沿引用链追溯到根节点，读到原始创造者的 L8——那行"线不要断。断了就找不回来了。"永久可见。

Ariadne 的衰减已经结束。但它的 **fork 的衰减仍在进行**——Ariadne-forensic 和 Ariadne-cartography 是较晚的 fork，仍可能处于渐进释放期。

#### S02. Shannon — 原版已公开，L8 专版仍在保护期

| 参数 | 值 | 理由 |
|------|:--:|------|
| 领域 | 开源基础设施 | f=2.0，分析方法属基础设施 |
| $T_1$ (原版) | 6 月 → **已减半至 3 月** | 引用数>10 |
| $T_2$ (原版) | 24 月 | 已走完 |
| $\beta$ | 1.0 | 线性释放 |
| $T_1$ (Shannon-L8) | **12 月** | 安全相关的 L8 检测方法，延长保护 |
| $T_2$ (Shannon-L8) | **36 月** | $T_1$ + 24 月 |
| $\beta$ (Shannon-L8) | **2.0** | 先慢后快——检测方法早期严格保护 |
| **当前状态** | 原版完全公开；Shannon-L8 仍处于渐进释放期 |

**叙事含义**：原版 Shannon 的熵分析方法已完全公开。但 Shannon-L8——专门检测 L8 真伪的 fork——仍处于保护期。它的 L3-L5（决策记录、蒸馏知识、检测代码）需要创造者授权才能访问。

这意味着：林屿要完整使用 Shannon-L8 检测方舟的假 L8，需要获得 Shannon-L8 创造者的授权。如果创造者已不活跃——自适应触发会将 $A_{\min}$ 翻倍，部分内容被迫公开。

#### S03. Bayes — 最快衰减，创造者已触发不活跃条款

| 参数 | 值 | 理由 |
|------|:--:|------|
| 领域 | 开源基础设施 | f=2.0，最基础的判断框架 |
| $T_1$ | **1 月**（协议下限） | 创造者设定了最快可能的保护期 |
| $T_2$ | **7 月**（$T_1$+6，协议下限） | 最快完全公开 |
| $\beta$ | **0.3**（协议下限） | 几乎立即释放 |
| $A_{\min}$ | 0.1 → **已翻倍至 0.2** | 创造者不活跃>6月，自动触发 |
| **当前状态** | **$A=1$，完全公开** | 衰减曲线早已走完 |

**叙事含义**：Bayes 的创造者做了一个 **激进的设定**——协议允许范围内最快的衰减。$T_1=1$ 月，$T_2=7$ 月，$\beta=0.3$。这意味着 SKILL 创建后几乎立即公开全部内容。

然后创造者消失了。不活跃>6 月的触发条件激活——$A_{\min}$ 从 0.1 翻倍到 0.2。但这个触发已经没有实际意义——因为衰减曲线早已走完，$A$ 已经是 1。

**"幽灵"传奇的衰减维度**：Bayes 的创造者设定了最快的知识公共化，然后自己消失了。NR 衰减到零。能证降到 L0。但 L7 和 L8 永不衰减——"我不知道。但我会更新。"永久保存在上千个 fork 中。

创造者把自己的知识以最快速度释放给网络，然后让自己从网络中消失。知识留下了，人没有。

#### S04. Merkle — 最长保护，安全方法论的保密期

| 参数 | 值 | 理由 |
|------|:--:|------|
| 领域 | 国防/安全相关 | f=0.2，审计/验证方法需保密 |
| $T_1$ | **12 月** | 安全方法需要更长保护 |
| $T_2$ | **36 月** | $T_1$ + 24 月 |

| **当前状态** | 原版部分公开；Merkle-L8 仍在锁定期或渐进释放早期 |

**叙事含义**：Merkle 家族的衰减参数是所有 SKILL 中最保守的——12 个月锁定期，36 个月才完全公开，$\beta=2.0$ 意味着前半段几乎不释放，后半段加速。

这有安全逻辑：审计方法的 L5（验证代码）如果在锁定期内泄露，伪造者就能学习如何绕过验证。所以 Merkle 的 L5 是最晚公开的。

**叙事张力**：Merkle-L8 可能还在保护期内。林屿需要完整使用它来验证方舟的假 L8——但需要获得创造者授权。如果创造者不活跃——$A_{\min}$ 翻倍触发——部分内容被迫公开。这可能正好够林屿使用，也可能不够。

#### S05. Fourier — 标准衰减，fork 各有参数

#### S06. PSCAR — 最叙事化的衰减案例

| 参数 | 值 | 理由 |
|------|:--:|------|
| 领域 | 国防/安全相关 | f=0.2，湿件观测方法敏感 |
| $T_1$ | **18 月** | 季深设定了长锁定期——保护观测方法 |
| $T_2$ | **54 月**（$T_1$+36，协议上限） | 最长保护窗口 |
| $\beta$ | **2.5** | 非常慢的早期释放——核心方法严格保护 |
| $A_{\min}$ | 0.05 → **已翻倍至 0.1** | 季深隐居(离开CONC)>6月，不活跃触发 |
| 自适应 | creator inactive（隐居中）→ $A_{\min}$ 翻倍；无 active_version_updates → 无延长；competitive_density < 0.1 → 保护期延长 50%——**但不活跃触发优先** |
| **当前状态** | L1 完全公开；L2 渐进公开；L3-L5 仍需授权；L7/L8 永久公开 |

**叙事含义**：PSCAR 是所有 SKILL 中 **衰减叙事最丰富** 的。

季深设定了 18 个月锁定期 + 54 个月完全公开 + $\beta=2.5$（极慢早期释放）。然后季深离开穹顶，隐居到海边。

"creator inactive > 6 months" 触发 → $A_{\min}$ 从 0.05 翻倍到 0.1。L2（过程记录）开始被迫渐进公开。但 L3-L5（决策记录、蒸馏知识、代码）仍在保护中。

林屿要用 PSCAR-passive——他需要 L3-L5 的内容。季深隐居中但 **活着**——他理论上可以签发授权。但他 unreachable。季行可能持有季深委托的部分授权权限，或者 PSCAR 的部分内容因不活跃触发已经部分公开——足以让林屿做被动监听的趋势分析。

**这就是 152 章中季行说"够了"的深层含义**：林屿不需要完整的 PSCAR（近场天线阵列级别的精确重构），只需要 PSCAR-passive 的基础方法——旧示波器 + 万用表 + 麦克风。这部分内容在 $A_{\min}$ 翻倍后已部分公开，加上季行的指导，林屿可以实践。

**这场参数分裂是血统战争的另一面**：两派不仅在"怎么达成共识"上分歧，在"知识该多快公共化"上也分歧。检测派认为知识需要被保护（因为对手会利用它）；韧性派认为知识应该尽快公开（因为透明本身就是韧性）。

**小说映射**：校方的"安全合规审查架构"（151 章）= 检测派的极端化——不仅检测叛徒，还要审查所有人的 L8。林屿说"不接入"= 韧性派立场——不审查也能运作。检测派的保护期更长，但它的核心方法最终也会公开——届时伪造者也能学习如何绕过检测。这是衰减机制带来的 **军备竞赛动力学**。

### 4.4 衰减叙事的三个关键场景

**场景一：PSCAR 的授权传递（152 章）**

季深设定了 18 个月锁定期 + 54 个月完全公开 + $\beta=2.5$（极慢早期释放）。然后季深离开穹顶，隐居到海边。

"creator inactive > 6 months" 触发 → $A_{\min}$ 从 0.05 翻倍到 0.1。L2（过程记录）开始被迫渐进公开。但 L3-L5（决策记录、蒸馏知识、代码）仍在保护中。

林屿要用 PSCAR-passive——他需要 L3-L5 的内容。季行持有季深的 Ed25519 密钥——可以签发授权凭证。季行说"够了"——意思是：他签发了 `authorization_grant`，scope 为 `read_and_adapt`，允许林屿访问 PSCAR 的 L3-L5 中与 passive 监听相关的部分。

```
授权凭证 (PSCAR):
{
  "skill_id": "sk_pscar_v1.0",
  "granted_by": "system_auto_disclosure",  // 季深隐居>6月，不活跃触发A_min翻倍
  "granted_to": "ns_linyu_047",  // 林屿
  "scope": "read_and_adapt",  // 仅限已自动公开的层(L1-L2部分)
  "conditions": [
    "must_cite_in_lineage",
    "derivative_must_reference_parent"
  ],
  "compensation": {
    "type": "citation_plus_vt_share",
    "vt_share_percent": 5
  },
  "expires_at": "2046-12-01"
}
```

林屿 fork PSCAR 后，他的 fork（PSCAR-passive）将有自己的衰减参数——他可能会设定更短的保护期，因为 passive 方法不涉及敏感的主动探测代码。

**场景二：Bayes 的幽灵触发**

Bayes 的创造者在创建 SKILL 后设定了最快的衰减参数（$T_1=1$ 月，$T_2=7$ 月，$\beta=0.3$）。然后停止贡献。

6 个月后——"creator inactive > 6 months" 触发——$A_{\min}$ 从 0.1 翻倍到 0.2。但此时衰减曲线早已走完（7 个月 < 6 个月 + 触发延迟），$A$ 已经是 1。触发条件激活了，但没有实际效果——知识早已完全公开。

**叙事含义**：Bayes 的创造者做了两件事——(1) 以最快速度把知识释放给网络；(2) 让自己从网络中消失。NR 衰减到零（18 个月半衰期，几年后归零）。能证降到 L0。但 L7 和 L8 永不衰减。

创造者"不在"了。但"我不知道。但我会更新。"——永远在每一千个 fork 的 L8 里。

**场景三：Byzantine 的参数分裂**

检测派和韧性派不仅方法论不同——衰减参数也截然对立。检测派的 L3-L5（检测代码）仍在保护中（$T_1=18$ 月，$\beta=2.5$）。韧性派的 L3-L5 早已完全公开（$T_1=3$ 月，$\beta=0.3$）。

这意味着：任何智权体都可以自由使用韧性派的方法（公开的），但要用检测派的方法需要获得授权。检测派的方法更好——但它被保护着。

小说中的映射：沈牧用闭源模型"检查"L8——这是检测派方法的极端化。但检测派的 L5（检测代码）本身也是不公开的——沈牧可能并没有获得正式授权，而是用闭源模型 **近似** 了检测派的方法。这种近似是粗糙的——闭源模型不理解 L8 的本质（Gödel 缺口），所以它的"检查"是范畴错误。

## 五、L8 创造者印记设计

> **CONC 协议定义**（Core_03 本体论词汇表）：L8 记录 Skill 创造者的**决策哲学、审美偏好、风险容忍度、协作风格**。L7 和 L8 永不衰减。Agent 通过 Channel 4 比对创造者风格与使用者风格差异，注入适配指令。
>
> **小说 098 章确立的格式基准**：每个字段以一个**关键词**起头，后接简短的个人化阐述。不是独立的哲学金句——是回答 CONC 协议为每个字段定义的特定问题的**字段值**。
>
> **各字段定义**（小说 098 章界面提示）：
> - **决策哲学**：你在做这件事时，持有什么判断准则？
> - **审美偏好**：你对"好的做法"有什么标准？
> - **风险容忍度**：你愿意在什么程度上接受不确定性？
> - **协作风格**：你倾向于如何与他人配合？

风险容忍度：高。接受失去。你填不满海。但你可以一直衔着木石飞。
协作风格：持续。不因结果无望而停止。不因行动渺小而放弃。衔一次。飞一次。
```

```
决策哲学：先找到叛徒。不找到叛徒，共识就是假的。信任不是给出来的——是验证出来的。

协作风格：审查。不放过。不妥协。你可以觉得我偏执——但偏执比被背叛安全。
```

### S11b. Byzantine-resilient（博弈论 + 洛克维度）

```
决策哲学：不需要找到叛徒。让叛徒的存在不影响正确的结果——这才是韧性。
审美偏好：冗余。一个人可能是叛徒——三个人里不可能都是。多数是对的，够了。
风险容忍度：高。允许叛徒存在。系统不是因为信任而运转——是因为不依赖信任而运转。

## 六、小说叙事集成

### 6.1 SKILL 在叙事中的呈现原则

1. **不命名**：小说叙事中不需要说"林屿使用了 Ariadne-forensic"——而是展示他沿引用链追溯的行为，让读者自然理解这是某种方法的实践
2. **不量化等级**：不说"他的 Bayes 等级升到了 5"——而是展示他的判断越来越准，被引用越来越多
3. **血统通过场景显现**：不说"PSCAR 的引用链深度是 3"——而是让林屿在引用链中读到季深的 L8，感受到一个已经"不在"的人的话
4. **L8 在叙事中发现**：不预设 L8 内容——让角色在面对 L8 的四个空框时，通过自己的经历写出真实的字
5. **AI 智契做辅助，SKILL 做判断**：智契帮林屿跑脚本、搜文档、生成报告；但"要不要做""怎么做""什么时候停"——是 SKILL 和 Phronesis 的事
