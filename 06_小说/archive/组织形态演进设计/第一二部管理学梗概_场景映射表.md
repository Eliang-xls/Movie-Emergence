# 第一二部管理学梗概：场景映射表

> 目的：将现代管理学理念转化为可落地的小说场景细节，确保每条理念都有明确的人物、章节和戏剧时刻。所有学术概念不直接出现在对话中——它们通过人物行动、选择和后果"渗透"进故事。

---

## 一、第一部（2027–2029）：现代企业管理的胜利与早期裂缝

### 1. Coase 交易成本理论 → "公司的意义"

| 维度 | 细节 |
|------|------|
| **核心理念** | 企业存在的理由是内部交易成本低于外部市场交易成本 |
| **小说场景** | 江远向 VC 陈述穹顶的扩张逻辑，或向季深解释为什么需要自己招人而非外包 |
| **建议章节** | 第 01 章（创业初期）或第 05 章（A 轮融资后） |
| **人物** | 江远 |
| **叙事方式** | 江远在融资 pitch 或团队会议中自然说出："公司的意义就是减少交易成本。外面找一个 AI 研究员，每次谈判、签合同、沟通需求，成本加起来比我们自己养一个贵得多——还不一定能理解穹顶的方向。" |
| **伏笔** | 这句话在第二部被现实反转——当 CONC 的模块验证和预共识协议将"外部协作的摩擦"降到比内部更低时，穹顶存在的唯一理由就瓦解了 |

### 2. 亚马逊"双披萨原则" → 沟通通道的直觉锚点

| 维度 | 细节 |
|------|------|
| **核心理念** | 团队规模不超过两张披萨能喂饱的人数（约 5-7 人） |
| **小说场景** | 季深拒绝扩大核心研究团队的理由——或叶澄的数据遥测提供了"双披萨"的量化证明 |
| **建议章节** | 第 05 章（人员扩张）或第 07 章（甜蜜点讨论） |
| **人物** | 季深 / 叶澄 |
| **叙事方式** | 季深对新招的研究员们说："人太多了——超过两张披萨能喂饱的人坐在一起，讨论就变成汇报。"——这是他朴素的直觉。到第 07 章，叶澄的遥测数据给了这个直觉一个冰冷的量化证明。 |
| **理论呼应** | 与 $C = N(N-1)/2$ 的沟通通道爆炸形成直觉-量化的双层锚定 |

### 3. Dunbar 数（150 人社交上限）→ 生物学的冰冷天花板

| 维度 | 细节 |
|------|------|
| **核心理念** | 灵长类新皮层比例与有效社交关系数量存在定量约束，人类约 150 人 |
| **小说场景** | 穹顶超过 150 人时，季深突然发现自己叫不出新来的工程师名字——Dunbar 数的"生物学提醒" |
| **建议章节** | 第 05 章末尾或第 07 章开头 |
| **人物** | 季深 |
| **叙事方式** | "季深走在三楼的走廊上。走廊比一个月前长了——不是物理长度，是人。有人跟他打招呼，'嗨季深'。他点了点头。但他不认识那个人。穹顶有 157 个人了。他的大脑装不下。" |
| **深层映射** | 这不是冷漠——是生物学。江远靠管理层级来扩展控制范围，但层级每增加一层，实践判断力就衰减一分。Dunbar 数是"认同型向心力"的自然边界线。 |

### 4. 亚马逊"六页纸备忘录" → 对抗会议熵

| 维度 | 细节 |
|------|------|
| **核心理念** | Bezos 禁止 PPT，要求会议提案写成六页纸叙述文，开会时集体默读 |
| **小说场景** | 江远在穹顶超过 50 人后推行的沟通改革 |
| **建议章节** | 第 05 章 |
| **人物** | 江远 |
| **叙事方式** | "从下个月开始，所有的项目提案不要给我 PPT。写叙述文——六页以内。开会前十五分钟，所有人大读，读完再讨论。"江远在周一早会上宣布。"口头汇报是噪音——你开口的那一刻，信息就开始衰减。写下来才能压缩。"工程师们面面相觑。有人在笔记上写："六页。好的。" |
| **伏笔** | 到第二部，六页纸变成十二页、二十页，"为写而写"的形式主义吞噬了改革的初衷——流程本身成为新的熵增源 |

### 5. Google 的"20% 时间" → 从创造意志到 KPI 的异化

| 维度 | 细节 |
|------|------|
| **核心理念** | 工程师可用 20% 工时做自己感兴趣的项目，Gmail/AdSense 由此诞生，但随规模和绩效压力增长而名存实亡 |
| **小说场景** | 江远在穹顶早期推行"自由探索时间"；后来被悄悄压缩 |
| **建议章节** | 第 05 章（推行）→ 第二部（消亡） |
| **人物** | 江远（推行者）→ 季深（观察者） |
| **叙事方式（推行）** | "还有一件事。"江远在入职培训的最后说，"你们每五个工作日里，有一天是自由的。做任何事——做个新模型、写个开源工具、或者什么都不做只是在白板上画画。这是穹顶给你们的信任。" |
| **叙事方式（消亡）** | 到第二部，当季深经过那间会议室时，看到墙上的标语还在——"20% 自由探索时间"——但下面的字已经被新贴的 OKR 季度目标覆盖了一半。走廊上没有人停下来看它。 |
| **理论呼应** | 这是 CONC 熵减引擎中"创造意志的释放"在公司制下的昙花一现——它证明了这个方向是对的，也证明了它在公司制框架下不可持续 |

### 6. OKR/KPI 管理 → 标准化生产力的双刃剑

| 维度 | 细节 |
|------|------|
| **核心理念** | 目标与关键成果管理、绩效考核——现代企业效率的基石也是创造力的窒息网 |
| **小说场景** | 江远将 OKR 引入穹顶的过程；季深对"对齐 OKR"的反感 |
| **建议章节** | 第 05 章 |
| **人物** | 江远（推行者）vs 季深（抗拒者） |
| **叙事方式** | "我们需要 OKR。"江远在白板上写下三个字母，"目标公开、进度透明、结果可衡量。不然两百个人各自朝不同的方向跑。"季深看着那三个字母。他想说点什么，但没开口。他想起自己过去三个月做的事——盯着屏幕上的光点，记录它们的位置变化，试图理解一种他不理解的现象。他没法把这件事写成一个 OKR。"我的目标是理解涌现"——这不是一个合格的 O。"关键成果：三篇论文"——这更可笑。 |
| **理论呼应** | 直接为第五章的"温差"提供戏剧化呈现——"工程师们沉迷于对齐 OKR 和写论文"的根源 |

## 二、第二部（2035–2040）：管理的天花板与裂口

### 7. Spotify Squad/Tribe 模型 → 公司制内"准策元"实验的失败

| 维度 | 细节 |
|------|------|
| **核心理念** | 小型跨职能自治团队（Squad），通过 Tribe/Chapter/Guild 矩阵管理——公司制内部最接近 CONC 策元理念的实验 |
| **小说场景** | 江远在穹顶感受到协调熵爆炸后，推行"穹顶 Squad"改革——以失败告终 |
| **建议章节** | 第二部早期（第 10-14 章之间） |
| **人物** | 江远 |
| **叙事方式** | "从下个季度开始，我们把工程部拆开。"江远在全公司会议上宣布。"每个 Squad 五到八个人。全栈。有自己的产品、自己的 backlog、自己的决策权。公司不告诉你们做什么——你们自己决定。"会议室里有人鼓掌。这是穹顶最激进的组织实验。（几个月后）Squad A 需要 Squad B 的一个 API 接口——但 Squad B 的产品优先级不同。Squad A 的项目经理去找江远，江远让两个人协调。协调了一个月。Squad C 的工程师辞职了——他被竞业协议锁在原地，但他说"我宁可回家种地也不想再写 KPI 了"。 |
| **失败的本质** | 不是 Squad 模式错了——是公司制的产权结构和向心力框架（强制型+能力型）与自治团队的信任型协作存在结构性冲突。这个失败为 CONC 策元的诞生提供了"在公司体制内解决不了"的必要性证明。 |

### 8. T22 向心力类型切换 → 理解的诞生与跨越的不可能

| 维度 | 细节 |
|------|------|
| **核心理念** | 公司向心力有七种类型（生存强制/制度锁定/能力放大/社会资本/认知路径依赖/认同/人格魅力），其中认同型随规模递减，强制型+能力型随规模递增——公司变大时不是"向心力衰减"，而是"类型切换" |
| **小说场景** | 江远深夜独自在办公室的内心戏——他不是不懂，他是懂了但无法跨越 |
| **建议章节** | 第二部中期（第 16-18 章之间） |
| **人物** | 江远 |
| **叙事方式** | "江远坐在办公桌前。窗外硅谷的灯海一直延伸到山脚。他知道季深是对的。他知道竞业协议锁住的不是人才——是仇恨。他知道穹顶的 OKR 系统正在把工程师变成填表机器。他比任何人都更清楚地看到了这个系统的天花板。但他不能停。穹顶不是一家公司——穹顶是一个承诺。对投资人的承诺，对客户的承诺，对 5000 个家庭的房贷和孩子的学费的承诺。季深要的是理解。他要的是责任。这两个方向在那间小办公室里还能并排写在白板上。现在白板早就被绩效看板取代了。" |
| **理论基础** | CONC T22——江远的困境不是人品问题，是"认同型向心力随规模递减"的结构必然。他被系统反向塑造了。他的悲剧在于：他是整部小说中最理解新范式必然性的人之一，但他是那个最无法跨越的人——因为他就是旧范式本身。 |

### 9. Coase 的"反刍" → 穹顶逻辑的自我瓦解

| 维度 | 细节 |
|------|------|
| **核心理念** | 如果外部交易成本低于内部管理成本，企业边界应该收缩——Coase 理论的逆命题 |
| **小说场景** | CTO 陈维明或财务负责人在董事会上算了一笔账——穹顶的边际成本曲线已经越过最优边界 |
| **建议章节** | 第二部中期（第 14-17 章之间） |
| **人物** | 陈维明 / 财务负责人 |
| **叙事方式** | "这是一个奇怪的数字。"财务负责人在董事会上投出幻灯片。"穹顶每增加一个工程师，他产生的净价值在连续六个季度下降。不是他能力不行——是我们内部的协调成本已经超过了把他放进来的收益。"陈维明没有说话。他想起了季深十年前说过的话："人太多了。"他当时以为那是社交障碍。现在他知道——那是工程学。 |
| **理论呼应** | 这是 Coase 理论的逆命题在小说中的实现——CONC 改写了"外部交易成本"的定义，使穹顶的"边界收缩"从理论可能变成现实压力 |

### 10. 效能分叉（Efficacy Divergence）→ Sophia 与 Phronesis 的分道扬镳

| 维度 | 细节 |
|------|------|
| **核心理念** | 科层制可以维持 Sophia（理论智慧/标准化产出），但系统性地衰减 Phronesis（实践判断力） |
| **小说场景** | 石田直子的独白："做四年设计，天枢帮我做完了……到头来我只是天枢的设计翻译"——这是效能分叉在个体身上的微观切片 |
| **建议章节** | 第 21 章《石田》 |
| **人物** | 石田直子 |
| **叙事方式** | 已经在原作中出现——重构方案建议强化这一场景的理论深度：石田的话不仅是抱怨，它是**效能分叉的个体证词**。"天枢（AI 工具）帮我把设计做完了——我应该高兴。但我没有。因为做设计和用 AI 做设计不是同一件事。前者是判断——这个配色对吗？这个交互流畅吗？这个细节用户会在意吗？后者是翻译——把我脑子里模糊的判断翻译成天枢能理解的参数。四年过去了。我变成了天枢的翻译。这是我的工资单的增长曲线。这不是我的技能增长曲线。" |

## 叙事原则

1. **从不解释学术概念**——Coase、Dunbar、T22 等名词不出现。理念通过人物行动和后果"渗透"。
2. **每个理念至少有一个具体的"身体感受"场景**——Dunbar 数不是一句话，是季深叫不出名字的尴尬瞬间。
3. **理念的引入和理念的失败之间有首尾呼应**——Coase 在第一部的豪言在第二部被反刍；六页纸在第一部的创新在第二部变成形式主义；20% 时间在第一部的理想在第二部变成墙上的褪色标语。
4. **理念是背景板，人物是前景**——读者不需要理解 T22，但读者需要感受到：江远的竞业协议不是因为他变坏了，是因为穹顶变大了。
