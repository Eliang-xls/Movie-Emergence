穹顶　027　八百毫秒

二〇三〇年·夏｜内部规格书的逆向审计记录

顾清在研发中心那套对研究员完全开放的共享文档库里，像排雷一样逐行翻阅一份关于天枢模型的底层交互规格书。她原本只是想确认几个认知心理学的交叉引用文献，搜索框的返回值却把她带到了这份文档最隐秘的安全阈值章节。

搜索词是 phronesis 相关底层配置。

检索结果的第三条，命中了一个她在任何会议上都没见过的内部物理文件名：tianxu_spec_v2.1_safety_thresholds.md。

她移动鼠标，点进去。

在「交互熔断机制」的段落，第一条赫然写着：

当系统特征提取器命中未知的未定义场景（Undefined Scenario）时，约束层必须强制挂起该调用，并由前端 UI 亮出资料来源缺口与人工复核入口。
等待人工答复的挂起超时（Timeout）：设定为八百毫秒。

顾清盯着屏幕，把这几行字反反复复读了两遍。

她绝不是在反对在界面上加入暂停提示。她反对的，是这群为了追求并发效率的人，竟然把一次关乎系统生死的「强制人工复核」，在代码里压缩成了一个仅用于通过验收测试的、冰冷的物理时间常量。

八百毫秒（800ms）。

她在脑子里调出了精确的人体生理参数：成年人一次正常的、无意识的眨眼，大约需要三百到四百毫秒。八百毫秒，只相当于两次半的眨眼。

两次半的眨眼。

在这个只够视神经把屏幕上的光子信号转成脑电波的瞬间里，八百毫秒够不够一个坐在电脑前、满脑子被 KPI 压得快要崩溃的审核员，在物理上真正意识到：他此刻点下鼠标的操作，正在跳过一个可能致命的数据缺口？

她不知道。没有任何临床实验能给出绝对安全的阈值。

但她确信一点：等待一个活人开口，该给多少毫秒，不该由一个躲在机房里写接口规格文档的人，用一个拍脑袋的 `Thread.Sleep(800)` 常量，来替全世界所有可能被系统影响的活人做决定。

她操作鼠标，在 PDF 阅读器里把「八百」这个数字用红色高亮圈了出来。

紧接着，她又把后面那个带工业流水线意味的词——「验收线（Acceptance Criteria）」也圈了出来。

在这两个红圈之间，她用触控笔硬生生画了一个双向箭头。在箭头上，她用键盘敲下三个字：

太短了。

她推开椅子，直接走向电梯间。目标三楼，P-3 实验室。

电梯上行的时候，轿厢里发出轻微的钢缆拉扯声。她站在轿厢中央，脑子里全是那个 800ms 的数字。

季深正陷在转椅里，盯着右侧屏幕上一份底层代码的 Git 差异对比工具（Diff）。屏幕上被切成左右两列，左边是旧代码，右边是新代码，被删除的行标着红色减号，新增的行标着绿色加号。

顾清连门都没敲，大步走过去，直接把那台带着触控笔标记的轻薄本，拍在了季深那张堆满草稿纸的防静电桌面上。

屏幕上正好显示着她刚才圈出的那个红圈。

「这份被锁死在底层的安全规格参数，你看过吗？」她问。

季深的目光从绿色的代码行上移开，扫了一眼屏幕。

「没有。」

「这是你们在草案原型里定下要人停下来的那个三秒。」顾清说，「到了产品规格书里，被业务线砍成了八百毫秒。一个物理时长参数。」

季深盯着那个被红圈圈出的数字，看了一分钟。他眼镜的镜片上反射着屏幕的冷光。

「宪章那五条戒律里，我没有写任何时间常量。」他的声音沉了下去。

「那这八百毫秒，连让人完整地读完一行报错提示都不够。它到底够干什么？」顾清的语气像刀一样。

季深没有立刻回答。

他猛地推开转椅站起来，走到那面布满污痕的旧白板前，双手插在工装裤的口袋里，站了一会儿，又转过身走回桌前。这是他遇到极棘手的系统死结时特有的反应。

「八百毫秒，最多只够让操作员在视网膜层面上意识到，屏幕的 UI 刚才似乎卡顿了一下。」季深说，「它不够让人在脑子里调出复核逻辑，更不够让人敲键盘写下一段像样的异议说明。」

「如果时间根本不够，那业务侧的那帮人，为什么还要煞费苦心地把它硬编码进这套规格书里？」

「因为在这套工业机器里，所有的合规审查都必须被量化成可以被测试脚本验证的数字。」季深的声音透出一种无力感，「没有具体数字的软性防御，QA（质量保证）部门的自动化测试用例就跑不通验收。无法验收，产品就不能上线。」

「所以，只要他们填上了一个哪怕是杀人的数字，那个『不负责任』，在流程上就摇身一变，变成了『合规且足够』？」顾清冷笑了一声。

「因为业务线天天在后面拿鞭子抽着催交付。」季深盯着桌子，「一旦上面催进度，底下写代码的人就会随便塞一个能让绿灯亮起的常量。这个数字一旦写进去、通过了编译，它在公司高层的眼里，就变成了这套系统已经安全的铁证。」

顾清没有再多说一句废话。她直接拉开键盘，在这份内部文档的批注系统里，用很硬的措辞敲下一段要求强制回滚的修订指令：

UI 界面上的物理暂停时长（Pause Duration），禁止被用作任何自动化测试直接通过或静默拒绝的底层验收条件（Acceptance Criteria）；

任何被触发的高危场景调用，必须在界面前端同时强制弹出四个无法被脚本屏蔽的要素：原始数据的索引范围、必须由第二名持密钥者人工触发的复核物理开关、永久固化的不可逆异议记录库（Immutable Log），以及暴露给受影响者的后续申诉 API 路径。

顾清敲键盘的速度极快，每一下都像敲在法庭的质证席上。写完之后，她从头到尾读了一遍，然后移动光标，把句子里的两个「应（Should）」字全部删掉，替换成在代码逻辑中具有强制力的「须（Must）」。

季深站在她身后，看着屏幕上的那段话。他伸出手，在键盘上敲下最后一句防御补丁：

时间延迟的阻尼算法，仅仅能在物理感官上提醒操作员这套系统需要被叫停。它不能替操作员做出判断，更不能量化为停顿多少毫秒才算是在道德上尽到了『审慎』的义务。

「你这句备注，写得像一句不该出现在规格书里的东西。」顾清看着那行字。

「正因为它不该出现在这里，才要写在这里。」季深收回手，「规格书是这栋楼里唯一会被逐字读完的文件。」

「也会是最先被下一次修订删掉的那一行。」顾清把光标停在那句话的末尾，没有按删除键，「但这一次，我同意把它留在提交日志里。」

他们把这份带着火药味的强制修订请求（Merge Request），直接扔回了那个负责编写安全规格的评审小组池子里。没有任何人敢在物理层面保证，这种直接阻碍业务线狂飙的改动会立刻被合并进主分支。

在提交请求的附件栏里，季深附上一封纯文本的短邮件：

我们不是在反对系统级界面的暂停提示（Pause UI）。

我们是在反对，你们把在物理上仅仅是『被强制卡顿过 800ms』的行为，在合规报告上等同于操作员在逻辑上已经进行过『深思熟虑的审慎（Prudence）』。这是偷换概念。

评审小组的回复系统，在三天后的下午才弹出一个冰冷的自动回执弹窗。

只有系统预设的一行灰字：

提交已确认入库。状态：挂起（Pending）。待引入下一轮跨部门联合评审会讨论。

没有承诺任何具体的处理期限。也没有抄送给任何级别的负责人。

顾清拔下自己的 U 盘，离开三楼的时候，电梯口的数字指示灯正发出轻微的蜂鸣，缓慢地跳动着。

从红色的 3 降到 1，中途又被人按停了两次。在这栋全天候运转的大楼里，电梯的调度算法永远优先满足那些急切的呼叫。

电梯门在底楼无声地滑开。一楼大厅里的冷白色吸顶灯光，瞬间泼在她的防风衣上，亮得没有温度。

她走出轿厢，高跟鞋踩在打过蜡的大理石地面上。她走路的步伐比进电梯时快得多，每一步都带着明确的指向。

回到自己那个角落里的工位，她没有去碰那台冰冷的工作机。

她翻开那个封皮磨损的私人笔记本，翻到空白的一页，用红笔重重地写下一句话。

这不仅仅是在记录今天的荒谬，这是在刻下一条对抗异化的认知锚点：

只要 800ms 这个杀人的常量被成功塞进了底层的规格文档，它就会在所有的进度表上，异化成一个理直气壮的「足够了」。

写完这句，她盯着那三个字看了一会儿，瞳孔里倒映着纸面的红色。然后，她合上了笔记本。
