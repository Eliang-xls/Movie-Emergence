穹顶　025　谁先说安全

二〇三〇年·春｜穹顶科技总部会议室

江远把一本厚达八十多页的《天枢系统规格白皮书》拍在了胡桃木会议桌上。纸张之间挤压出一声沉闷的气响。

翻开白皮书，里面分三个部分：产品定义、交付 API 清单、安全承诺章节。

前面两部分密密麻麻印满了性能参数、并发吞吐量和毫秒级响应延迟。而第三份——「安全承诺章节」，此刻赫然存在着大片空白。

在那些空白处，江远之前用红笔龙飞凤舞地写下三个大大的「TBD」（To Be Determined，待定）。后来审稿时，他又觉得这三个字母看起来太像是在敷衍资方，于是用黑笔把其中两个涂成了黑块。

客户在问安全。纳斯达克的承销商在问安全。上下游的算力租赁方也在问安全。

他们问的，不是在学术沙龙上喝着红酒讨论的抽象伦理词汇。他们要的是合同上的担保：你们跑在这个黑盒里的资料，是从哪个带版权的库里抓出来的？谁拥有 root 权限能查看日志？如果在极端工况下系统发生逻辑冲突，谁拥有拔掉网线的物理暂停权？如果出了波及几百万人的生产事故，谁的法人名字会被钉在起诉书的第一排？

宽大的会议桌能坐十二个人。此刻偌大的空间里只有江远，和产品线的总负责人小陈。小陈手里攥着一支黑色水性笔，笔帽已经被他焦虑的牙齿咬出一圈坑洼的白印。

「江总，安全这一章，到底该怎么填？」小陈看着那堆黑块，声音有点发虚。

「就写我们目前在物理层面上能兑现的约束。」江远的身体压在桌沿上，眼神很冷，「绝对不写任何超越我们控制力哪怕一微秒的扯淡承诺。」

「可是，那些政企客户的采购部要的是『万无一失』的保证书。」小陈辩解。

「保证书是拿去骗散户的。」江远毫不留情地打断他，「我们是在给他们提供一套工业级杀伤武器的说明书。说明书必须带着残忍的物理边界、清楚的免责条款、以及绝对受限的适用工况范围。保证书里什么风险都没有，那才是最大的风险。」

江远把身体靠回真皮椅背里。

他脑子里突然闪过半年前，季深在罗纳德·里根机场的候机大厅里发来的那条加密消息：他们要的不是模型在底层到底安不安全。他们要的是，当系统搞砸的时候，能有一份漂亮的报告，知道该去追究谁的责任，或者，可以理直气壮地免除谁的责任。

当时他看到那条消息，回了一句：既然规则是这样，那下一次我们再去国会山，你站到台前，拿他们想要的东西给他们看。

季深没有回。

现在，这支笔递到了他自己手里。

他伸手拖过键盘，调出了季深和顾清在那个不眠之夜、在内部库里死磕出来的那份《宪章草案》。

江远看的不是那些关于人格或哲学的云端废话。他像一个逐字审读法案的律师，只提取那份草案里最硬核的程序指令：

必须在系统启动前强验证资料来源的合法性范围；日志系统必须完整保留原始数据的增删痕迹；当面临高压并发时，必须在前端界面上强制亮出被折叠的冲突材料；对于高危级别的调用，必须在架构里硬编码一条允许人工强行介入挂起（Suspend）、请求第二人独立复核、以及允许当事人提交异议申诉的回退路径。

他把这套充满反骨的代码逻辑反反复复读了一遍。他不是搞底层算法的，有些涉及张量变换的限制词，他甚至要盯着屏幕咬文嚼字地看上两遍，才能确切理解它在工程上的阻断威力。

读完之后，他在纸质白皮书的页边距上，用力写下一句批注：

能够被白纸黑字写进 SLA（服务等级协议）合同里的，只有这些带刺的程序，没有其他。

江远把这些底层逻辑，用商业法务的语言，一条一条砸进了规格书里。

第一条：针对高影响级别的生产场景，客户必须在 API 触发前，在代码层面显式声明调用资料的边界范围与最终用途。

第二条：系统生成的任何自动摘要，禁止在算法层面上通过权重倾斜，去压平或掩盖原始输入中的数据缺口、矛盾点及任何未经数字签名的未决条件。

第三条：调用链上的任何一名人类授权者，均拥有无条件触发 Emergency_Stop（紧急暂停）指令的物理权限；执行挂起操作的处理人，必须在系统日志中强制录入中断理由、波及节点的物理范围、以及重启系统所必须满足的前置复核条件。

第四条：API 访问权限严格按照调用场景和时间窗口进行动态降级分层；任何涉及敏感级别资料的底层访问，后台必须强制生成不可篡改的双向审计记录，该记录的清除权限不由任何单一节点或单方利益体静默控制。

在这四条里，他没有写入任何一个统一的系统等待时间常量。没有把「暂停机制」包装成一种体现模型自我反思能力的公关噱头。更没有向客户承诺，只要买了这个企业版，穹顶的这套代码就能像神一样自动识别出所有的商业风险。

小陈看着屏幕上这四条简直是在「劝退」客户的铁律，咽了一口唾沫。「江总……我们把条款写得这么死，客户那边的采购官会不会觉得，我们自己都不信自己的技术？」

「在这个连明天哪家公司会倒闭都不知道的硅谷，只有真正自信的操盘手，才敢在合同里明码标价地写上限制条款。」江远冷笑了一声，「那些不敢在合同里写限制、满嘴『包治百病』的初创公司，要么在后台悄悄藏了致命的木马，要么就是在拿客户的数据当筹码赌博。藏和赌，在物理世界里的下场是一样的——只是引爆时间早晚的差别。」

写到「数据授权条款」这一页时，江远敲键盘的手指停了足足半分钟。

作为 CEO，穹顶的商业护城河当然要求把客户的生产数据尽可能深地锁在自家生态里。可江远同样清楚，如果在授权协议上，仅仅是在穹顶的后台加上一把只有自己能打开的黑盒锁，那么「数据安全」这个词，很快就会在资本的异化下变成一场绑架。

他的手指重重地砸在键盘上，在规格文档的最末尾，补上一句反向约束：

授权的签署，不得作为拒绝向数据所有方披露处理逻辑的豁免牌；穹顶在拒绝或缩小客户访问范围时，必须在限定工时内提供经得起独立审计的技术理由与复核推翻路径。

写完这句话，他把这段文字在脑子里过了两遍。

他觉得「适当的技术理由」这个词在法律上太软了。他想直接把「适当」改成「充分」。

但手指在退格键上悬停了一秒。随后他又想：在法庭上，到底谁有资格用仪器测量什么叫作「充分」？

最后，他保留了「适当」这个词。软了一分，但至少在面临诉讼时，它不会变成一张可以直接被对方律师用来绞杀穹顶的空头支票。

那天深夜离开公司前，江远拿起手机，给季深发了一条加密信息：

最新一版的企业版安全规格书，已经全部引用了宪章草案里的底层程序逻辑。范围限定、强制暂停、独立复核和异议堆栈，一个字节都没落，全写进去了。

季深的回复没有他想象中那么快。足足等了二十分钟。

收到。请务必在库里保留宪章草案的历史 Diff 版本和那张影子反例表。

江远盯着屏幕上这行克制的回复。他原本以为季深至少会发一句「干得漂亮」或者「有劳了」。季深根本没有打算为这份商业合同做任何个人背书。

江远在输入框里打出「你放心」三个字。

看着这三个苍白的字，他大拇指迅速按下了删除键。

他重新敲下一行不带感情色彩的工作汇报：

版本号（v0.3）的索引已经打在规格文档的每一页页脚。那份反例表作为物理附件，一并入档。

几个月后，穹顶科技凭借这份堪称苛刻的规格书，从几家巨头嘴里抢下了一份涉及高约束性基础设施行业的准入协议。

这份协议里没有一个字节涉及实机接入。它签的是一套资格和口径：穹顶的企业版被列入对方的采购名录，代价是安全规格逐条接受对方独立审计，且每一条都要拿得出可以现场验证的证据。

对方是某国的一家巨型能源财团。他们的数据中心直接管控着该国大区电网的核心调度中枢。那个调度系统如果因为一行代码的越权而发生雪崩，物理世界里瞬间陷入黑暗的，将是三座常住人口超千万的超级城市。

在那座装潢奢华的顶层会议室里，合同的物理条款整整博弈了六个星期。仅仅是「安全应急响应章节」，双方的法务团队就互发了十一稿修订红线版本。

正式落笔签字那天，能源财团的首席法务官坐在长条会议桌的对面，盯着江远，提出了最后一个问题：

「江先生，贵司为什么坚决不肯在最终协议里，写下『保证系统绝对安全运行』？」

江远迎着对方的目光，没有丝毫退让。

「因为在计算机科学和热力学定律里，『绝对安全』是一个违反物理常识的谎言。」江远说，「我们在合同里写的每一个字，都是在精确地界定：当系统不可避免地发生崩溃时，到底该追究哪个物理节点的责任、通过什么探针来发现断点、以及在多少毫秒内必须物理切断电源。」

法务官盯着江远看了一会儿，紧绷的嘴角微微松弛了一点。

「这比一张印满漂亮话的保证书，要有用得多。」对方说。

安全章节里，没有画任何大饼。它只罗列了适用的边界坐标、苛刻的审查触发条件、数据投喂的物理限制，以及发生争议时的仲裁代码。

签字用的镀金万宝龙钢笔，是客户那边递过来的。墨水是纯黑的。

江远在最后一页的虚线处签完字，把笔帽稳稳地扣上，发出一声清脆的金属咬合声，双手递还给对方。

对方没有伸手接。「留作纪念吧，江总。」

江远没有客套，顺手把那支沉甸甸的钢笔插进了西服内侧的口袋里。

那支笔，他后来一直随身带着。不是因为牌子有多名贵。

是因为在签下那个名字的瞬间，只有他自己清楚，他握着笔管的右手手指，在承受着多大的张力，产生了极细微的、不可控的生理性颤抖。

只有他自己知道。
