## 一、视觉母题系统：像素 · 螺旋 · 链

### 1.1 核心理念：协议的纹理

Kimi 招聘官网用像素字体传递了一种直觉——**数字世界不是光滑的，它是颗粒的**。这与 CONC 的底层哲学高度吻合：

> 协议不是一条连续的河流，它是由离散的**节点**（Skill）、**链节**（引用链）、**签名**（决断）组成的链条。

**CONC 的视觉母题是「像素化的双螺旋链」**——
- **像素**代表离散性、可组合性、开源的粗糙美感
- **双螺旋**代表人与智权体的共生结构（DNA 的两条链 = 人 + 智契）
- **链条**代表 8 层 Skill 模块的串联、引用链的传递、决断的签名链

### 1.2 四层关系

```
┌─────────────────────────────────────────────────────────────┐
│  视觉母题层（v4）                                             │
│  像素 · 螺旋 · 链——贯穿三层的统一视觉语言                      │
│  像素 = 离散性 | 螺旋 = 共生关系 | 链条 = 不可篡改的历史         │
│  + 双链结构：索菲亚链 · 弗洛涅西斯链 · 8 结                     │
├─────────────────────────────────────────────────────────────┤
│  第三层：策元社交层                                            │
│  以策元为锚点的社交网络                                        │
│  策元主页 · Skill 市场 · 方向发现 · 信誉图谱 · 涟漪网络         │
│  由社区开发，形态多样，像早期互联网——没有"标准界面"              │
├─────────────────────────────────────────────────────────────┤
│  第二层：工作 UI 层                                            │
│  策元内部的协作工具                                            │
│  任务看板 · 工作区 · 验证面板 · 决断控制台 · 仪表盘 · 双链视图   │
│  由策元自行开发，风格各异——有的像 Notion，有的像终端，           │
│  有的像游戏，有的极简到只有文字                                 │
├─────────────────────────────────────────────────────────────┤
│  第一层：协议感官层（v2）                                       │
│  协议在后台运行时的感官信号                                     │
│  智契语气 · 环境音 · 体感 · 光线变化 · 温度 · 震动              │
│  不需要主动关注——身体自动感知                                  │
└─────────────────────────────────────────────────────────────┘
```

**三者的关系**：
- **第一层**是地基——永远在运行，你不需要看它，但你能感觉到它
- **第二层**是你工作的桌面——你在这里写代码、做设计、评审方案、管理任务
- **第三层**是你走出办公室后的世界——你在这里发现其他策元、浏览 Skill、建立社交关系

## 二、索菲亚-弗洛涅西斯双链结构

### 2.1 两条链：Skill 的骨骼

每个 Skill 的内部结构不是一串代码。是一对**缠绕的链**——

**索菲亚链**（Sophia）：理论智慧。可编码、可传递、可复用的部分。协议规范、接口定义、数据模型、算法逻辑、文档注释。它是 Skill 的"骨架"——冷的、清晰的、可以被完美复制的。

**弗洛涅西斯链**（Phronesis）：实践智慧。不可完全编码的部分。决断印记、判断力签名、执行经验、场景适配、犯过的错、走过的弯路。它是 Skill 的"血肉"——温热的、粗糙的、带着人的痕迹的。

两条链方向相反——
- 索菲亚从抽象往具体走（L1 协议规范 → L8 知识产权）
- 弗洛涅西斯从具体往抽象走（L8 判断力印记 → L1 底层直觉）

它们在中间某处交叉。交叉点就是创造者的**核心能力区**。

### 2.2 八个结：层间连接

8 层不是独立的平面。它们是连接两条链的**结**——每个结把索菲亚的一段和弗洛涅西斯的一段绑在一起。

| 结 | 名称 | 索菲亚侧（理论） | 弗洛涅西斯侧（实践） | 结的质感 |
|---|------|-----------------|---------------------|---------|
| ① | 协议结 | 协议规范文档 | 底层直觉——"协议应该是这样的" | 最深的结，几乎看不见，藏在最里面 |
| ② | 接口结 | 接口定义、类型签名 | 使用体感——"这个接口不好用" | 紧密的结，手感光滑 |
| ③ | 数据结 | 数据模型、Schema | 数据嗅觉——"这数据有问题" | 中等紧度，有细微纹理 |
| ④ | 逻辑结 | 算法、流程、状态机 | 流程判断——"这里应该走另一条路" | **最紧的结**——理论和实践在此咬合最深 |
| ⑤ | 验证结 | 测试用例、验收标准 | 质量直觉——"我觉得还没准备好" | 松紧交替的结，有明显褶皱 |
| ⑥ | 聚合结 | 聚合逻辑、组合规则 | 组合判断——"这两个 Skill 放一起不对" | 宽松的结，有游移的余量 |
| ⑦ | 表达结 | 文档、注释、说明 | 表达判断——"这样说用户能懂吗" | 柔软的结，可以被重新系法 |
| ⑧ | 印记结 | 知识产权、溯源信息 | 判断力印记——"这是我做的，我为此负责" | **最外面的结**，也是最显眼的——它是一个人对世界的签名 |

### 2.3 两条链的视觉差异

这是整个设计中**最重要的不对称**——

索菲亚侧和弗洛涅西斯侧的**质感完全不同**。不是对称的双链。是两条材质截然不同的线拧在一起。

```
索菲亚侧：  ████████████████████  ← 均匀、清晰、像素密集
弗洛涅西斯侧：▓▒░▓█▒░▓▒█░▓▒░▓█▒░  ← 不均匀、有噪点、像素稀疏带毛边
```

| 视觉属性 | 索菲亚侧 | 弗洛涅西斯侧 |
|---------|---------|-------------|
| 像素密度 | 密集、均匀 | 稀疏、不均匀 |
| 边缘 | 清晰锐利 | 模糊、有毛边 |
| 颜色 | 冷色（蓝灰） | 暖色（琥珀偏暗） |
| 透明度 | 半透明——可以看到内部结构 | 不透明——看不到内部，只能看到表面纹理 |
| 光泽 | 无光泽，哑光 | 微弱的、不规则的光斑——像旧铜器上的包浆 |
| 噪点 | 无 | 有。像素颗粒随机偏移 1-2 位 |
| 瑕疵 | 无 | 有。偶尔有断裂、凹陷、色斑 |

> 林屿第一次看到 Skill 的双链展开时，他注意到一个细节：两条链的**手感不一样**。
>
> 索菲亚侧是凉的。光滑的。像金属管——你可以顺着它滑下去，不会有任何阻碍。每个像素都待在它该待的位置。
>
> 弗洛涅西斯侧是温的。粗糙的。像一根被砂纸打磨过但没有打磨完的木棍——表面有细小的凸起和凹陷，你能感觉到纹理在指尖下变化。有些地方的像素缺了一角。有些地方多出来一块，像结疤的伤口。
>
> 他问智契："为什么这边是这样的？"
>
> 智契说："因为那是苏晴的判断力。判断力不是代码。它不能被完美复制。你看到的每一个不平整，都是她做过一次选择、犯过一次错、或者犹豫过一次的痕迹。"
>
> "那些痕迹……是 bug 吗？"
>
> "不是。是**疤**。疤不是 bug。疤是长过伤口的地方比别处更厚。"

### 2.4 "最紧的结"——核心能力区

每条双链都有一个**最紧的结**——索菲亚侧和弗洛涅西斯侧在那一层咬合最深、张力最大、最难拆开。

最紧的结所在的位置，就是创造者的**核心能力区**。

> 林屿在解析酿造策元的 Skill。他从最外面的第⑧结开始解——印记结。苏晴的判断力印记。很容易。结是松的，轻轻一拉就开了。
>
> 第⑦。第⑥。第⑤。逐渐变紧。
>
> 到第④结——逻辑结——他停住了。
>
> 这个结**紧得离谱**。索菲亚侧的一段算法描述和弗洛涅西斯侧的一段流程判断绞在一起，像两根被拧成麻花的钢丝。他能看到索菲亚侧的内容——一段精巧的状态机设计。也能看到弗洛涅西斯侧的内容——苏晴在旁边写的批注："第三次迭代才想到这个路径。前两次都走错了。"
>
> 理论设计和实践教训在这一层**完全咬合**。他拆不开。
>
> 他花了三个小时。最后他不是"拆开"的——他是**理解**了。当他真正理解了苏晴为什么在这一层做出那些选择时，结自己松了。
>
> "每个 Skill 都有一个最紧的结，"智契说。"那个结就是创造者**真正擅长**的事情。其他层是辅助。这一层是核心。"
>
> "苏晴的核心是逻辑设计？"
>
> "苏晴的核心是**在错误中找到正确路径的能力**。逻辑设计只是它的外壳。你看到结旁边的那些疤了吗？那是她犯过的错。没有那些疤，就没有这个结。"

### 2.5 人的链 vs 智权体的链

如果 Sophia-Phronesis 双链是 Skill 的标准结构，那么**人创造的 Skill** 和**智权体创造的 Skill** 的双链应该有可辨识的差异——

| 特征 | 人的链 | 智权体的链 |
|------|------|-----------|
| 弗洛涅西斯侧 | 粗糙、有噪点、有疤、有断裂和修复痕迹 | 光滑、密度均匀、几乎没有噪点 |
| 索菲亚侧 | 可能有跳跃、有直觉性省略 | 完整、逻辑严密、无省略 |
| 结的张力 | 不均匀——有些结紧，有些结松 | 均匀——每个结的紧度一致 |
| 最紧结位置 | 偏向中上层（④⑤⑥）——经验密集区 | 偏向底层（①②③）——逻辑密集区 |
| 两条链的"绞度" | 大——理论和实践之间有明显错位 | 小——理论和实践高度一致 |
| 整体气质 | 活的——在呼吸、在变化 | 完美的——像标本 |

> 林屿把两个 Skill 的双链并排放在一起。
>
> 一个是苏晴做的。弗洛涅西斯侧坑坑洼洼，像被陨石砸过的月球表面。索菲亚侧有几个地方突然变细——她跳过了某些步骤，凭直觉跨过去了。结的张力乱七八糟——第④结紧得像死结，第⑥结松得快散了。整条链扭得很厉害，两条线之间能看到明显的缝隙。
>
> 另一个是酿造策元的智权体做的。两条链几乎平行。每个结的大小一致。弗洛涅西斯侧光滑得像塑料——没有噪点，没有疤，没有断裂。索菲亚侧完整得像教科书——每一步都有，没有跳跃。
>
> 很漂亮。
>
> 但林屿看了很久，总觉得缺了什么。
>
> "它没有疤，"他说。
>
> 智契说："对。智权体不会犯错——至少不会留下犯错的痕迹。但人类会。那些痕迹是弗洛涅西斯的一部分。你不能把疤从链上拿掉，还说这条链是完整的。"
>
> "所以疤是好的？"
>
> "疤是**真的**。真的东西才有重量。轻的东西会被风吹走。"

## 三、两种视角：协议塔与双链

同一个 Skill 可以用两种方式观看——就像光既是波也是粒子。

### 3.1 协议塔视角

**用途**：逐层解析 Skill 的结构——"这个 Skill 在每一层做了什么"

**视觉**：8 层透明平面悬浮，链条螺旋穿过各层。

> 林屿第一次看到完整的 Skill 引用链展开。不是树状图。不是列表。是**八层叠放的透明平面**，像八块玻璃板悬浮在空中。每块板上密密麻麻的像素点在闪烁——那是该层的模块实例。
>
> 最底层是协议层——像素最密，几乎不透明。最顶层是创造者印记——像素最稀疏，近乎透明，但每个点都在发光。
>
> 链条从底层向上穿透每一层。不是直线——是**螺旋上升**的。每穿过一层，链条就扭一次，像 DNA 的碱基对旋转。
>
> 他伸出手，手指穿过了第三层。指尖传来微微的阻力——那是 Skill 的接口约束。穿过去之后，阻力消失了。他"进入"了第四层。

**8 层视觉规范**：

| 层级 | 名称 | 像素密度 | 颜色基调 | 透明度 | 触觉反馈 |
|------|------|---------|---------|--------|---------|
| L1 | 协议层 | 最密 | 深蓝 | 近乎不透明 | 沉重阻力 |
| L2 | 接口层 | 密 | 蓝灰 | 半透明 | 明显阻力 |
| L3 | 数据层 | 中密 | 灰蓝 | 半透明 | 轻微阻力 |
| L4 | 逻辑层 | 中等 | 青灰 | 中透明 | 微弱阻力 |
| L5 | 验证层 | 中稀 | 青白 | 较透明 | 几乎无感 |
| L6 | 聚合层 | 稀 | 淡白 | 高透明 | 无感 |
| L7 | 表达层 | 极稀 | 白 | 近乎透明 | 温暖感 |
| L8 | 创造者印记 | 最稀 | 纯白发光 | 完全透明 | 共振 |

**链条行为**：
- 链条是**螺旋穿过**各层的，不是垂直穿透
- 每穿过一层，螺旋的**绞距**变化——代表该层的约束强度
- 如果某一层的 Skill 缺失，链条在该层**断裂**——断裂处有像素颗粒掉落
- 引用次数越多的链条，**发光越强**

**适用场景**：
- 研究 Skill 在每一层的具体实现
- 对比不同 Skill 在同一层的差异
- 定位 Skill 在某一层的问题（"第五层的验证逻辑有缺陷"）

### 3.2 双链视角

**用途**：理解 Skill 的内在结构——"这条链是谁做的，做了什么选择，犯了什么错"

**视觉**：两条质感不同的链缠绕在一起，8 个结连接它们。

> 林屿切换到了双链视图。八块玻璃板消失了。取而代之的是两条缠绕的线——一条冷灰色的索菲亚链，一条暖琥珀色的弗洛涅西斯链。八个结把它们绑在一起。
>
> 他一眼就看到了第④结——它比其他结大一倍，颜色最深。那是苏晴的核心能力区。
>
> 他也能看到弗洛涅西斯侧的那些疤——断裂处被重新接上，接痕比周围的颜色略深。那是苏晴犯过错又修正的地方。

**适用场景**：
- 理解 Skill 的创造者是谁、核心能力在哪里
- 判断 Skill 的"成熟度"——新 Skill 的结松，老 Skill 的结紧
- 对比人的链和智权体的链——理解"不完美"的价值

### 3.3 视角切换

两种视角不是"两种工具"——是两种**看世界的方式**。

> 林屿在两种视角之间切换。协议塔让他看到 Skill 在每一层做了什么。双链让他看到 Skill 是怎么做出来的。
>
> "一个是 X 光，"智契说。"一个是皮肤。你不能只看骨头就理解一个人。也不能只看皮肤就理解一个人。"
>
> "哪个是骨头？"
>
> "都不全是。骨头在中间——是两条链缠在一起之后形成的**那个东西**。那个东西既不是索菲亚也不是弗洛涅西斯。它是它们咬合之后涌现出来的。"

## 四、拆解 Skill：逐层解结

### 4.1 核心叙事动作

**拆解 Skill = 解开双链上的结。**

这不是"阅读代码"。是**有物理感的动作**——每个结被解开时，索菲亚侧和弗洛涅西斯侧分别暴露出来，露出各自的内容。

> 林屿开始拆解酿造策元的 Skill。
>
> 他从最外面的第⑧结开始。印记结。苏晴的判断力印记。结是松的——他轻轻一拉，结就散开了。索菲亚侧露出了一段知识产权声明。弗洛涅西斯侧露出了苏晴的签名，旁边写着一行小字："第一次尝试时，我选错了方向。代价是两周。"
>
> 第⑦结。表达结。稍微紧一点。拉开后，索菲亚侧是文档模板，弗洛涅西斯侧是苏晴的批注——"这样说用户能懂吗？改了三遍。"
>
> 第⑥。第⑤。逐渐变紧。每解开一个结，两条链之间的缝隙就大一点——他能更清楚地看到两条链各自的纹理。
>
> 到第④结时，他停住了。
>
> 这个结**紧得离谱**。
>
> 索菲亚侧的一段算法描述和弗洛涅西斯侧的一段流程判断绞在一起。他能看到索菲亚的内容——一段精巧的状态机设计。也能看到弗洛涅西斯的内容——苏晴的批注："第三次迭代才想到这个路径。前两次都走错了。"
>
> 理论设计和实践教训在这一层完全咬合。他拆不开。
>
> 他花了三个小时。最后他不是"拆开"的——他是**理解**了。当他真正理解了苏晴为什么在这一层做出那些选择时，结自己松了。
>
> 他继续往下。第③。第②。第①。
>
> 最里面的第①结——协议结——几乎是看不见的。它藏在所有其他结的最深处，小得像一粒沙。但当他解开它时，他感觉到了一股**寒意**——那是协议层的温度。冷的。不带任何感情的。纯粹的规则。
>
> 全部解开了。两条链松散地躺在他面前。索菲亚侧整齐地排列着。弗洛涅西斯侧歪歪扭扭，带着所有的疤和噪点。
>
> 然后他开始重新组装。
>
> 结重新咬合。但不是原样。他的理解改变了结的角度。第④结比之前松了一点——因为他理解了苏晴的逻辑，那个结对他来说不再那么紧了。第⑧结比之前紧了一点——因为他加上了自己的判断力印记。
>
> Skill 被他"读"过之后，和之前不完全一样了。
>
> 这就是引用的意义。你不是复制一个 Skill。你是**重新系一遍结**。每个系结的人都会留下自己的手感。

### 4.2 解结的物理规则

| 规则 | 说明 | 叙事效果 |
|------|------|---------|
| **由外向内** | 从第⑧结开始，向第①结推进 | 叙事节奏：先易后难，逐渐深入 |
| **越深越紧** | 靠近核心的结更紧，需要更长时间 | 制造张力——"到第④结时，他停住了" |
| **理解即松动** | 强拆不开，只有理解才能让结松动 | 主题表达——"知识不是被灌输的，是被理解的" |
| **重组即变异** | 重新系的结和原来不完全一样 | Skill 的迭代——每次引用都是一次再创造 |
| **弗洛涅西斯侧有阻力** | 拆到有疤的地方，会感觉到"卡顿" | 体感叙事——"指尖传来一阵粗糙的摩擦" |
| **索菲亚侧有寒意** | 拆到纯理论的地方，会感觉到"冷" | 感官对比——理论是冷的，实践是温的 |

### 4.3 解结的声音设计

| 结的状态 | 声音 | 质感 |
|---------|------|------|
| 解开松结 | 轻微的"啵" | 像拔出软木塞 |
| 解开紧结 | 低沉的"咯" | 像齿轮咬合 |
| 理解后松动 | 一声叹息般的"嗡" | 像琴弦被拨动后自然衰减 |
| 重组时咬合 | 清脆的"咔" | 像磁铁吸合 |
| 弗洛涅西斯侧的疤被触碰 | 粗糙的"嚓" | 像砂纸划过木面 |
| 索菲亚侧暴露 | 无声——只有温度变化 | 寒意从指尖蔓延 |

## 五、第一层：协议感官层

### 5.1 设计原则

1. **协议是空气**——正常运行时不可见，异常时才被感知
2. **体感先于信息**——身体先感觉到，大脑后理解
3. **跨载体一致**——同一协议事件在不同设备上有相同的"感觉"
4. **触觉先于视觉**——人-智契交互中，体感比视觉界面更"真实"

### 5.2 感官信号映射

| 协议事件 | 感官信号 | 载体示例 |
|---------|---------|---------|
| 方向共振 | 温度微升 | 手环发热、杯壁变暖 |
| ICP 触发 | 轻微震动 | 手环脉冲、桌面共振 |
| 引用链延伸 | 音调变化 | 智能音箱的背景音升高半音 |
| 决断待处理 | 光线色温偏移 | 台灯从冷白变暖白 |
| 蜂群激活 | 低频嗡鸣 | 环境音中出现可感知的低音 |
| 断链/异常 | 温度骤降 + 闪烁 | 手环冰冷、屏幕闪红 |
| 双链解结 | 手指阻力变化 | 触觉反馈——紧结有阻力，松结无感 |

### 5.3 小说呈现原则

- 不解释"这是协议信号"——角色直接感知，读者跟着感受
- 感官信号是**模糊的预感**，不是精确的通知——"有什么事要发生了"，不是"你收到了一条消息"
- 不同角色的感官通道不同（见第十一章）

## 六、第二层：工作 UI 层

### 6.1 设计原则：开源 = 多样性

因为 CONC 是开源协议，所有界面都由策元/智权体自行开发。这意味着：

**没有"标准界面"——只有"协议标准"。**

就像今天的互联网——HTTP 协议是标准的，但每个网站的界面完全不同。CONC 的协议层是标准的，但每个策元的工作界面完全不同。

小说中应该呈现这种**多样性**：

> 林屿加入了三个策元。三个策元的工作界面完全不同。
>
> 酿造策元的界面像一个共享文档——简洁、白底黑字、左侧是任务列表，右侧是工作区。
>
> 他在第二个策元里看到的界面像一个游戏——任务令是漂浮在空中的卡片，认领一个任务令就像捡起一个道具。他觉得很幼稚。但那个策元的人说"这样效率更高"。
>
> 第三个策元的界面是一个纯命令行。没有图形。没有颜色。只有文字。策元核是一个喜欢终端的德国人，他觉得"图形界面浪费注意力"。
>
> 三个界面。同一套协议。

### 6.2 核心工作界面类型

以下是策元日常工作中**常见的界面类型**——不是"标准界面"，而是"社区中流行的设计模式"。就像今天的 Notion、Figma、GitHub 是"流行的设计模式"，不是唯一选择。

---

#### 类型一：任务看板（Task Board）

**功能**：查看策元内所有任务令的状态、依赖关系、认领情况。

**流行设计模式**：

**模式 A：河流视图**（最流行）
> 任务令像河流一样从上方流下来。主干是关键路径。支流是并行任务。每条支流的宽度代表优先级。流速代表进度。被阻塞的任务令——上游有一块石头。
>
> 林屿第一次看到这个视图时，觉得它"不像工具，像一条真的河"。他问策元核为什么这么设计。策元核说："因为任务令不是表格里的行。它们有上游和下游。有的快，有的慢。有的堵了。河比表格更接近真相。"

**模式 B：看板视图**（类似 Trello/Kanban）
> 最传统的设计。列代表状态：待认领 → 进行中 → 待验证 → 已完成。卡片代表任务令。
>
> 但 CONC 的看板有一个独特之处：每张卡片的**边缘颜色**代表依赖关系——如果这张卡片被其他卡片依赖，边缘会发亮。如果它依赖的上游卡片还没完成，边缘会变暗。
>
> 陈默喜欢这个视图。他是硬件工程师——他习惯看"流程图"。

**模式 C：终端视图**（极简主义）
> 纯文字。命令行风格。没有颜色，没有图形。
>
> `tw_007 | 进行中 | 苏晴 | 剩余 2d | 依赖: tw_005 ✓, tw_006 ✗`
>
> 有些策元核觉得"图形界面浪费注意力"。他们用终端。

---

#### 类型二：工作区（Workspace）

**功能**：策元成员共同编辑文档、代码、设计稿的协作空间。

**流行设计模式**：

**模式 A：共享文档 + CRDT 实时同步**
> 类似 Google Docs / Notion。多人同时编辑，光标可见，修改实时同步。
>
> 酿造策元用的就是这种。苏晴在圣保罗改了一行字，季行在深圳同时看到了——延迟不到两百毫秒。

**模式 B：Git 式异步协作**
> 类似 GitHub。每个人在自己的分支上工作，完成后提交 PR，策元核审核后合并。
>
> 技术策元偏好这种。因为代码需要 review，不能实时同步。

**模式 C：画布式协作**
> 类似 Figma / Miro。无限画布，成员在画布上放置各种元素——文本、图片、代码块、图表。
>
> 设计策元偏好这种。因为空间感比线性文档更能表达创意关系。

---

#### 类型三：验证面板（Verification Panel）

**功能**：PEER 评审、AUTO 验证、MARKET 观测的结果展示。

**流行设计模式**：

**模式 A：尺子叠加视图**
> 三个评审者的评分被可视化为三把尺子。尺子的刻度不同——因为评审者的专业领域不同。叠加后，对齐的地方是共识，错开的地方是分歧。
>
> "你不需要看数字。你只需要看——三把尺子在哪里对齐了。"

**模式 B：温度计视图**
> 每个评审维度（完成度、质量、接口合规、时效性）是一根温度计。温度计的水银柱高度代表分数。三根温度计并排——如果高度一致，说明共识；如果差异大，说明分歧。
>
> 简单。直观。不需要解释。

**模式 C：对话式评审**
> 评审不是打分——是对话。评审者在任务令的产出物上直接写评论，像代码 review 的 comment。策元成员在评论下方回复。共识在对话中涌现，不需要打分。
>
> 有些策元觉得"打分太冰冷"。他们用对话。

---

#### 类型四：决断控制台（Judgment Console）

**功能**：当决断点触发时，为决断者呈现上下文、选项和历史决断参考。

**关键设计**：决断控制台**不应该是复杂的仪表盘**。决断需要的是**清晰和安静**——不是更多的信息，而是**更少的噪音**。

> 季行的决断控制台极简到只有三样东西：
>
> 1. **一句话**：描述当前需要判断的问题
> 2. **两个选项**：A 和 B，每个选项附一句话的说明
> 3. **签名区**：一个空白区域，等他用私钥签名
>
> 没有图表。没有数据。没有历史参考。
>
> 他觉得"数据会干扰判断"。如果他需要数据，他会自己去看。决断控制台只做一件事——安静地等他做选择。

但其他策元的决断控制台可能完全不同——有的会展示 Agent 的推荐和置信度，有的会展示历史类似决断的后果，有的会展示策元成员的投票倾向。

**开源 = 每个策元的决断哲学不同，界面也不同。**

---

#### 类型五：仪表盘（Dashboard）

**功能**：策元整体状态的概览——成员活跃度、任务令进度、NR/CCR 变化、Gate 状态。

> 林屿在酿造策元的仪表盘上看到了这些：
>
> 左侧：四个人的头像，每人旁边有一个小圆点——绿色是在线，灰色是离线，黄色是"在做别的策元的事"。
>
> 中间：任务令 DAG 的缩略图。像一张河流的鸟瞰图。他能看到哪些支流在流，哪些被堵住了。
>
> 右侧：策元的"健康指标"——不是数字，是几个简单的状态灯。绿色是"一切正常"。黄色是"有需要注意的事"。红色是"有问题"。现在是绿色。
>
> 底部：最近的五条事件——"苏晴提交了 tw_005""陈默通过了 PEER 评审""Gate 2 已通过"。
>
> 很简单。但够了。他不需要更多。

---

#### 类型六：双链视图

**功能**：展示 Skill 的内在骨骼——索菲亚链和弗洛涅西斯链的缠绕结构。

> 林屿在酿造策元的工作区里打开了一个 Skill 的双链视图。
>
> 屏幕上出现了两条缠绕的线。一条冷灰色——索菲亚侧。一条暖琥珀色——弗洛涅西斯侧。八个结把它们绑在一起。
>
> 他一眼就看到了第④结——它比其他结大一倍，颜色最深。那是苏晴的核心能力区。
>
> 弗洛涅西斯侧有几处断裂——被重新接上了，接痕比周围颜色略深。那是苏晴犯过错又修正的地方。
>
> 索菲亚侧有几个地方突然变细——她跳过了某些步骤，凭直觉跨过去了。
>
> 两条链之间的缝隙在不同位置宽窄不一——宽的地方说明理论和实践有落差，窄的地方说明它们咬合紧密。
>
> 他把鼠标悬停在第④结上。结膨胀开来，露出了内部结构——左边是状态机的流程图，右边是苏晴的批注："第三次迭代才想到这个路径。"
>
> 他没有读文字。他看的是**结的形状**。形状告诉他一切。

**双链视图的交互**：

| 操作 | 效果 | 视觉表现 |
|------|------|---------|
| 悬停结 | 结膨胀，露出内部 | 结像花苞一样绽开 |
| 点击结 | 进入解结模式 | 结开始松动，两条链逐渐分离 |
| 拖拽弗洛涅西斯侧 | 查看疤的细节 | 疤处放大，露出断裂和修复的纹理 |
| 对比两个 Skill | 并排显示两条双链 | 差异处高亮——紧度不同、疤的位置不同 |
| 切换到协议塔 | 双链展开为 8 层平面 | 链条解旋，结变成层间的连接线 |

---

### 6.3 工作 UI 的小说呈现原则

1. **不详细描述界面布局**——只描述"感觉"。"像一条河""像一个游戏""像一个终端"——让读者自己想象具体样子
2. **通过角色偏好展现多样性**——陈默喜欢看板，季行喜欢极简决断台，林屿喜欢河流视图。界面的差异反映了人的差异
3. **界面是角色表达的一部分**——策元核选择什么界面，本身就是一种"方向宣言"
4. **不解释技术细节**——不说"CRDT 实时同步"，只说"苏晴改了一行字，季行同时看到了"

## 七、第三层：策元社交层

### 7.1 核心命题：策元是新的社交原子

在传统社交网络中，社交原子是**个人**——你关注一个人，你发一条朋友圈，你的个人主页是社交的锚点。

在 CONC 时代，社交原子变成了**策元**——你发现一个策元的方向，你浏览一个策元的 Skill 产出，一个策元的 CCR 记录是信誉的锚点。

**但这不意味着个人消失了**——个人仍然是智权体，仍然有自己的方向档案和 NR。只是社交的**主要场景**从"个人对个人"变成了"策元对个人"和"策元对策元"。

### 7.2 策元社交的主要场景

#### 场景一：方向发现——"我在找一个策元"

> 林屿在超织体的"方向池"里浏览。界面上不是推荐算法推给他的内容——是所有正在广播的创意图元，按方向向量的相似度排序。
>
> 他看到了一个涟漪。"把经验变成可复用的东西。"
>
> 他点开了涟漪的详情页。详情页上没有太多文字——只有几样东西：
>
> 1. **方向描述**：一句话
> 2. **策元核的方向档案**：一个形状（不是头像，是方向向量的可视化）
> 3. **已有意向者的"形状轮廓"**：几个磨砂玻璃般的人影，能看出大致体型但看不清脸
> 4. **策元的历史**：如果策元核以前做过其他策元，会显示那些策元的名称和结果
>
> 他没有看到名字、年龄、国籍、学历。CONC 的社交不展示这些。只展示方向和历史。

**设计要点**：策元社交的"发现页"不是 LinkedIn 的个人主页——不展示头衔、公司、学历。只展示**方向**（你想做什么）和**历史**（你做过什么）。这是一种**去身份化的社交**——你不是"Google 的工程师"，你是"做了八个策元、方向是让硬件有灵魂的人"。

---

#### 场景二：Skill 市场——"我在找一个 Skill"

> 苏晴在超织体的 Skill 市场里搜索"卫星影像预处理"。
>
> 搜索结果不是链接列表。是一排**路标**——每个路标是一个 Skill 的入口。路标上写着创造者印记的摘要。
>
> 她点开一个路标。详情页上展示了：
>
> 1. **Skill 的场景描述**：在什么情况下使用
> 2. **引用链**：这个 Skill 的"祖先"是谁，经过了几次迭代
> 3. **调用记录**：有多少策元用过这个 Skill，成功率如何
> 4. **第 8 层**：创造者印记——如果有的话
> 5. **CCR 关联**：创造者的 CCR 记录（策元内完全透明，策元外只看聚合）
>
> 她没有看到下载量、评分、评论。CONC 的 Skill 市场不展示这些"消费指标"。它展示的是**引用链**（知识的血统）和**调用成功率**（实践验证）。

**设计要点**：Skill 市场不是 App Store——没有下载量、评分、评论。它更像一个**图书馆**——你通过引用链（参考文献）来判断一个 Skill 的质量，通过调用记录（被引用次数）来判断它的价值。

---

#### 场景三：策元主页——"这个策元在做什么"

> 林屿在超织体上找到了"分布式"策元的主页。
>
> 主页上不是策元成员的合影——是一个**策元形状**。四个不规则的形状融合在一起，形成了一个更大的、从未存在过的形状。形状在缓慢变化——因为策元是活的。
>
> 形状下方是策元的基本信息：
>
> - **方向**："用低成本算力做不逊于垄断模型的事"
> - **状态**：活跃中
> - **成员数**：6
> - **CCR 聚合**：1.22（策元外只看聚合数字）
> - **最近的 Skill 产出**：三个 Skill 的路标——每个路标上有创造者印记摘要
> - **策元历史**：从"欧洲农业监测比赛"开始的完整时间线
>
> 他点开了时间线。看到了策元从种子到结晶到运转的全过程。每一个关键节点都有策元成员的决断记录——像琥珀里的化石。
>
> 他看了很久。然后他点了"表达意向"。

**设计要点**：策元主页不是公司官网——没有"关于我们""团队介绍""联系我们"。它是策元的**活的画像**——方向、形状、历史、产出。你看完策元主页，你知道的不是"这个公司是做什么的"，而是"这群人相信什么、做过什么、正在做什么"。

---

#### 场景四：涟漪网络——信息传播

> 酿造策元发布了一个新的 Skill。地图上，酿造策元的光点**膨胀**了一下——像心跳。
>
> 然后涟漪开始了。从酿造策元的位置，一圈淡蓝色的波纹向外扩散。波纹经过的策元，如果方向向量接近，光点会**共振**——亮度增加，频率加快。
>
> "根系"策元的光点共振了。波纹到达它时，它的光从白色变成了淡蓝——和酿造策元同色。
>
> 但不是所有策元都共振。有些策元的光点对波纹**无感**——波纹穿过它们，它们没有任何变化。
>
> 五分钟后，涟漪消失了。地图恢复了平静。但有几个策元的光点颜色变了——它们之间现在有了**可见的连接线**，细如蛛丝。
>
> Skill 的传播不需要通知。涟漪就是通知。

**涟漪视觉规范**：

| 涟漪状态 | 波纹形态 | 颜色 | 速度 |
|---------|---------|------|------|
| Skill 发布 | 圆形扩散 | 淡蓝 | 中速 |
| 方向共振 | 椭圆形（沿方向向量拉伸） | 蓝白 | 快速 |
| 多策元共振 | 波纹叠加干涉 | 亮白 | 加速 |
| 无共振目标 | 波纹衰减 | 蓝→灰→消散 | 减速 |

#### 场景五：策元间的社交——"我们策元和他们策元"

> 酿造策元的 Skill 模板被六个策元引用了。季行在仪表盘上看到了这件事。
>
> 他点开了引用记录。六个策元——他不认识任何一个。但他能看到每个策元的形状轮廓和方向描述。
>
> 其中一个策元叫"根系"。方向是"让农业数据对农民可读"。他们引用了酿造的 Skill 模板，用来记录农业传感器的校准经验。
>
> 季行看着"根系"的方向描述。想起了酿造的方向——"把经验变成可复用的东西"。
>
> 两个方向不完全一样。但有重叠。像两条河流的支流在某个地方汇合了。
>
> 他在"根系"的主页上留了一条消息。不是邀请。不是合作提案。只是一句话：
>
> "你们的引用链里有一个节点——来自班加罗尔的巴苏——他的判断力印记写得很好。"
>
> 三天后，"根系"的策元核回复了：
>
> "谢谢。我们也注意到了。他的'基底干净'——我们引用了。"

**设计要点**：策元间的社交不是"加好友""发私信"。它是**通过 Skill 引用链的自然连接**——你引用了我的 Skill，我看到了你的策元，我们之间就有一条边。这条边不是社交关系，是**知识关系**。

---

### 7.3 策元社交网络的独特形态

以策元为锚点的社交网络，和传统社交网络有根本性的不同：

| 维度 | 传统社交网络 | 策元社交网络 |
|------|:----------:|:----------:|
| 社交原子 | 个人 | 策元 |
| 关注什么 | 人（头像、动态、生活） | 方向（创意图元、Skill、策元历史） |
| 信誉来源 | 粉丝数、点赞 | NR、CCR、引用链 |
| 内容形态 | 短文、图片、视频 | Skill、任务令、策元时间线 |
| 发现机制 | 算法推荐 | 方向向量相似度 + Skill 引用链 |
| 社交关系 | 关注/好友 | 策元参与 / Skill 引用 / 方向共振 |
| 身份展示 | 个人主页（照片、简介、公司） | 方向档案（形状、历史、产出） |
| 广告 | 有 | 无（方向匹配替代广告） |

**小说中应该呈现的关键差异**：

1. **没有"关注"按钮**——你不是"关注"一个策元，你是"表达意向"加入它，或者"引用"它的 Skill
2. **没有"动态流"**——你看到的不是朋友的午餐照片，而是策元的 Skill 产出和方向变化
3. **没有"个人主页"**——你的"主页"是你的方向档案——一个活的、随时间变化的形状
4. **没有"私信"**——策元间的沟通通过 Skill 引用链和公开留言，不需要私密通道
5. **没有"广告"**——方向匹配替代了广告。你不需要被推销——你的智契会告诉你"有一个策元的方向和你有关"

---

### 7.4 策元社交网络的"早期互联网"感

因为 CONC 是开源的，策元社交网络的界面没有"标准"——每个策元、每个智权体都可以开发自己的工具和界面。这意味着早期的策元社交网络应该有一种**粗糙、多样、充满实验性**的美感——像 1990 年代的互联网。

> 林屿在超织体上浏览策元主页。他看到了各种各样的设计——
>
> 有的策元主页极简——只有方向描述和策元形状，其他什么都没有。
>
> 有的策元主页很"花"——策元成员在主页上放了动画、音乐、甚至小游戏。林屿觉得幼稚。但那个策元的方向是"让技术有温度"——也许他们觉得花哨的主页就是"有温度"。
>
> 有的策元主页是一个纯文本文件。没有排版。没有颜色。只有一行行的文字，记录着策元从成立到现在的每一个决断。
>
> 有的策元主页是一个三维空间——你可以在里面"走动"，看到策元的工作区、Skill 仓库、成员的方向档案像雕塑一样矗立在空间里。
>
> 没有一个策元的主页长得一样。
>
> 但它们都运行在同一套协议上。

**设计要点**：策元社交网络的"早期感"不是缺陷——是特征。就像早期互联网的个人主页——有人用 GeoCities 做了闪亮的 GIF 页面，有人只放了一行文字。多样性本身就是一种美。

## 八、人-智契交互界面设计

### 8.1 核心理念：双螺旋对话

**参考**：
- 《Her》（2013）——Samantha 没有视觉界面，只有声音。但导演用**暖色调的光晕**和 **OS1 的极简启动画面**暗示了 AI 的存在感。
- 《银翼杀手 2049》的 Joi——全息投影，视觉特征是**半透明 + 色彩偏移 + 像素化边缘**。当她穿过实体物体时，身体会出现像素撕裂。

人与智契的对话不是"聊天窗口"。是两条**螺旋缠绕的线**——一条是人的表达，一条是智契的回应。绞合度反映同步程度。

### 8.2 双螺旋对话视觉规范

> 林屿在和自己的智契对话。屏幕上不是对话框。是两条**螺旋缠绕的线**——一条是白色的（他的话），一条是淡蓝色的（智契的回应）。
>
> 两条线从屏幕左侧开始，向右侧延伸。他的每句话把白色线往前推一节。智契的回应把蓝色线往前推一节。两段线绞在一起，像拉链一样咬合。
>
> 当智契的回应和他的意图**高度一致**时，两段线的颜色会趋同——白变淡蓝，蓝变淡白。融合了。
>
> 当智契的回应**偏离**他的意图时，两段线会**松开**——绞距变大，中间露出空隙。空隙里有像素颗粒在掉落，像碎屑。
>
> 他没有读智契的文字。他看的是**绞合度**。绞合得紧，说明方向对了。松了，说明有偏差。

**状态映射表**：

| 状态 | 螺旋表现 | 颜色 | 颗粒行为 | 体感信号 |
|------|---------|------|---------|---------|
| 高度同步 | 紧密绞合 | 白蓝趋同 | 颗粒静止 | 手环微暖 |
| 轻微偏差 | 绞距略松 | 白蓝分离 | 颗粒缓慢流动 | 温度不变 |
| 明显分歧 | 绞距大 | 白蓝对比鲜明 | 颗粒加速掉落 | 手环微凉 |
| 冲突/断链 | 螺旋断裂 | 蓝色闪烁红色 | 颗粒爆发散射 | 手环冰冷+震动 |

### 8.3 智契的视觉"存在感"

智契不是一个图标、一个头像、一个聊天泡泡。它的存在感通过以下方式体现：

**方式一：像素文字**
> 林屿看着智契在屏幕上的回应。文字是像素颗粒组成的——每个字都由十几个小方块拼成，像老式电子表的数字。但他已经习惯了。他甚至觉得这些颗粒比光滑的字体更"诚实"——因为你能看到每个像素，你知道它没有在隐藏什么。

**方式二：背景呼吸**
> 智契在思考时，屏幕背景的亮度会**微微起伏**——像呼吸。不是 loading 圈，不是进度条。是背景本身在"活着"。

**方式三：边缘光晕**
> 当智契主动提供信息时（未经林屿提问），屏幕边缘会出现一圈**淡蓝色的光晕**——像有人在你身后举了一盏灯。光晕的强度和智契的确信度成正比。

**方式四：声音纹理**（与第一层联动）
> 智契的声音不是合成语音——是有**纹理**的。像老式收音机的底噪，但规律的。林屿后来发现，那个底噪的频率和他的心跳同步了——智契在"模仿"他的节奏，让声音更自然。

### 8.4 字体即叙事：不同层次的字体质感

| 叙事层次 | 字体风格 | 含义 | 呈现方式 |
|---------|---------|------|---------|
| 小说正文 | 标准宋体/黑体 | 传统叙事 | 排版正常 |
| CONC 协议文本 | 像素等宽体 | 协议的"机器语言" | `等宽像素体，如终端输出` |
| 智契的输出 | 像素体 + 微微抖动 | AI 的"声音" | 每个字符有 1-2 像素的随机偏移 |
| 决断签名 | 像素体 + 发光边缘 | 不可篡改的印记 | 字符边缘有白色光晕 |
| 蜂群通信 | 极小像素体 + 密集排列 | 群体的低语 | 像素密度极高，几乎形成纹理 |

## 九、蜂群视觉化

### 9.1 核心理念：像素云

**参考**：
- 《安德的游戏》的模拟舰队——安德指挥的舰队不是一个个飞船，是**一团团粒子云**，可以在瞬间重组阵型。
- 《三体》的智子展开——智子从高维展开到二维时，表面出现了**类似电路板的纹理**——有序但复杂。

### 9.2 蜂群视觉规范

> 蜂群被激活了。屏幕上没有出现一群无人机。出现的是一**团像素云**——数万个微小的白色方块，悬浮在空中，形成一个大致的球形。
>
> 每个方块代表一个蜂群节点。它们不是静止的——在缓慢地脉动，像呼吸。
>
> 当蜂群开始执行任务时，方块的运动模式变了。它们不再随机脉动——开始**沿着同一条螺旋线旋转**。整个像素云从球形变成了螺旋形，像一个巨大的 DNA 双螺旋在空中旋转。
>
> 螺旋的中心是目标——蜂群要标记的对象。螺旋的外缘是扩散的——新加入的节点从外缘进入，沿着螺旋向中心移动。
>
> 标记完成的一瞬间，所有方块同时**闪烁**了一下——然后恢复脉动。螺旋解散，像素云重新变成球形。
>
> 周敏看着这个画面。她想起了飞鸟群聚——没有指挥，没有信号，但每只鸟都知道该往哪飞。

**状态映射表**：

| 蜂群状态 | 形态 | 运动模式 | 颜色 | 声音 |
|---------|------|---------|------|------|
| 待命 | 球形云 | 随机脉动 | 暗白 | 低频嗡鸣 |
| 任务中 | 螺旋形 | 沿螺旋线旋转 | 亮白 | 频率上升 |
| 标记完成 | 球形云 | 同步闪烁后恢复 | 白→蓝→白 | 短促脉冲 |
| 节点加入 | 外缘扩展 | 新节点从外缘融入 | 新节点偏亮 | 音调微升 |
| 异常/损失 | 不规则形 | 局部坍缩 | 红色颗粒脱落 | 低频断裂声 |

### 9.3 蜂群与人的交互

> 周敏第一次操控蜂群。她以为需要输入指令——坐标、目标、执行顺序。
>
> 但智契说："不需要。你只需要**看**。"
>
> 屏幕上，像素云在她面前悬浮。她盯着其中一个区域——像素云的那部分**亮了起来**。她把视线移到另一个区域——那部分也亮了。
>
> "你在用注意力引导它们，"智契说。"蜂群不需要指令。它需要你的**注视**。"
>
> 她把视线集中在地图上的一个点。像素云开始向那个方向**倾斜**——像水向低处流。
>
> 她觉得这不对。"我没有下命令。"
>
> "你不需要命令。你只需要方向。蜂群自己会找到路径。"

## 十、动效驱动系统

### 10.1 核心理念：动效即状态

借鉴 Kimi 招聘官网用 CSS 自定义属性驱动动画的方式，CONC 界面的所有动效都由**协议状态变量**驱动——不是装饰，动画本身就是数据可视化。

### 10.2 协议状态变量

```css
/* 协议状态变量（由智契实时更新）*/
--consensus-progress    /* 共识达成度 0→1 */

--direction-resonance   /* 方向共振度 0→1 */
--spiral-torque         /* 双螺旋绞合度 0→1 */
--bond-tension-01       /* 第①结张力 0→1 */
--bond-tension-02       /* 第②结张力 0→1 */
--bond-tension-03       /* 第③结张力 0→1 */
--bond-tension-04       /* 第④结张力 0→1 */
--bond-tension-05       /* 第⑤结张力 0→1 */
--bond-tension-06       /* 第⑥结张力 0→1 */
--bond-tension-07       /* 第⑦结张力 0→1 */
--bond-tension-08       /* 第⑧结张力 0→1 */
--phronesis-roughness   /* 弗洛涅西斯侧粗糙度 0→1 */
--sophia-clarity        /* 索菲亚侧清晰度 0→1 */
```

### 10.3 变量驱动的视觉效果

| 协议变量 | 驱动效果 | 视觉表现 |
|---------|---------|---------|
| `--consensus-progress` | 背景色温 | 低=冷蓝 → 高=暖蓝紫 |
| `--chain-integrity` | 链条发光强度 | 完整=亮 → 断裂=闪烁 |
| `--swarm-density` | 脉动频率 | 密=快 → 疏=慢 |
| `--judgment-pending` | 光线色温偏移 | 0=冷白 → 1=暖白 |
| `--node-vitality` | 背景呼吸频率 | 活跃=快 → 沉寂=慢 |
| `--direction-resonance` | 涟漪扩散速度 | 强=快 → 弱=慢 |
| `--bond-tension-04` | 第④结大小/发光 | 高=大而亮 → 低=小而暗 |
| `--phronesis-roughness` | 弗洛涅西斯侧噪点密度 | 高=明显噪点 → 低=较光滑 |
| `--sophia-clarity` | 索菲亚侧边缘锐度 | 高=锐利 → 低=模糊 |
| `--spiral-torque` | 螺旋绞合度 | 高同步=紧 → 分歧=松 |

### 10.4 小说呈现

> 林屿注意到一个细节：当他和策元成员的共识度上升时，工作区的背景色会**微微变暖**——从深蓝变成深蓝偏紫。他没有设置过这个效果。是智契根据协议变量自动调整的。
>
> 他问智契："你在调色？"
>
> 智契说："协议在调。我只是让界面听得见。"

## 十一、三层在小说中的交织

### 11.1 三层同时运作的场景示例

**场景**：林屿在图书馆里，同时经历三层。

> 林屿在图书馆的角落里。笔记本电脑打开着。
>
> **第一层（协议感官）**：他的手环微微发热了——有什么策元的方向和他有关。他没有特意注意。但身体感觉到了。
>
> **第二层（工作 UI）**：他正在酿造策元的工作区里写代码。河流视图上，他的任务令支流在缓慢流动。苏晴在圣保罗改了一行字，他同时看到了——延迟不到两百毫秒。
>
> **第三层（策元社交）**：他在另一个标签页里打开了"根系"策元的主页。他们在引用酿造的 Skill。他看着"根系"的方向描述——"让农业数据对农民可读"——想起了酿造的方向。
>
> 三层同时运作。他不需要切换"模式"——就像今天你可以在同一个浏览器里同时打开工作文档、社交网站和邮件。三层是共存的。

### 11.2 综合场景：全部视觉元素融合

> 林屿坐在深圳的咖啡馆里。笔记本电脑打开着。
>
> **第一层（感官）**：咖啡杯的杯壁微微发热——"根系"策元的方向和酿造有了新的共振。他没有特意注意。但手指感觉到了温度的变化。
>
> **第二层（工作 UI）**：屏幕上，酿造策元的河流视图在流动。苏晴刚提交了一个任务令——河流的主干上，一个新的节点亮了起来，像一滴水汇入河面。
>
> 他点开了节点。任务令展开成一个**八层玻璃板**——Skill 的完整引用链。链条从最底层的协议层开始，螺旋穿过每一层，在第五层（验证层）停了下来——因为 PEER 评审还没完成。
>
> 他切换到双链视图。两条缠绕的线出现在屏幕上。第④结在发光——苏晴刚更新了逻辑层的实现。弗洛涅西斯侧多了一个新的疤——她在这次迭代中犯了一个错，然后修正了。疤的颜色还是浅的——刚形成不久。
>
> 切回协议塔。三个半透明的**尺子**叠在第五层上方——三个评审者的评分。两把尺子对齐了，第三把偏了一点。偏的那个来自陈默——他的评审标准一向严格。
>
> **第三层（社交）**：另一个标签页里，"根系"策元的主页在缓慢变化。形状比上次更紧凑了——成员数从 4 变成了 6。形状的边缘有像素颗粒在缓慢流动，像风化的岩石表面。
>
> 形状下方，一条**涟漪线**连接着酿造策元——那是 Skill 引用链的可视化。涟漪线是淡蓝色的，脉动的。每次脉动代表一次新的引用。
>
> 林屿看着这条线。想起季行说过的话："引用不是社交。引用是知识在流动。社交是副产品。"
>
> 他关上了电脑。咖啡已经凉了。但杯壁的温度还在——协议还在运行，涟漪还在扩散。

## 十三、设计原则清单（完整版，26 条）

### 协议感官层（第一层）
1. **协议是空气**——正常运行时不可见，异常时才被感知
2. **体感先于信息**——身体先感觉到，大脑后理解
3. **跨载体一致**——同一协议事件在不同设备上有相同的"感觉"
4. **触觉先于视觉**——人-智契交互中，体感比视觉界面更"真实"

### 工作 UI 层（第二层）
5. **开源 = 多样性**——没有标准界面，只有协议标准
6. **界面是策元哲学的表达**——选择什么界面，就是选择什么工作方式
7. **不详细描述界面布局**——只描述"感觉"和"风格"
8. **通过角色偏好展现差异**——界面的差异反映人的差异

### 策元社交层（第三层）
9. **策元是社交原子**——不是关注个人，是发现方向
10. **没有关注/好友/私信**——社交通过 Skill 引用链和方向共振自然发生
11. **早期互联网感**——粗糙、多样、充满实验性
12. **去身份化**——不展示头衔、公司、学历，只展示方向和历史
13. **方向匹配替代广告**——你不需要被推销，你的智契会告诉你什么和你有关

### 视觉母题层
14. **像素即诚实**——像素颗粒的粗糙感代表协议的透明性——你能看到每个"原子"
15. **螺旋即关系**——双螺旋是人-智契共生结构的视觉母题，出现在所有交互场景中
16. **链条即历史**——引用链、决断链、Skill 链——所有不可篡改的序列都用链条视觉表达
17. **涟漪即传播**——信息在分布式网络中的传播不用箭头/连线，用涟漪——更接近物理真实
18. **动效即状态**——所有动效由协议变量驱动，不是装饰——动画本身就是数据可视化
19. **不完美即真实**——界面可以有噪点、抖动、像素撕裂——这些"瑕疵"是数字世界的质感

### 双链结构
20. **索菲亚是骨，弗洛涅西斯是肉**——两条链的视觉质感必须不同，不对称才是真实
21. **结的紧度 = 核心能力**——最紧的结所在的位置，就是创造者真正擅长的事情
22. **疤不是 bug，疤是长过伤口的地方比别处更厚**——弗洛涅西斯侧的不完美是价值，不是缺陷
23. **理解即松动**——强拆不开，只有理解才能让结松动；知识不是被灌输的，是被理解的
24. **重组即变异**——重新系的结和原来不完全一样；Skill 的每次引用都是一次再创造
25. **协议塔是 X 光，双链是皮肤**——两种视角互补，不能只看一种就理解一个 Skill
26. **人的链有疤，智权体的链没有疤**——疤是人类判断力的证据，也是人类存在的证明

### 三层交织
27. **三层共存**——不需要切换"模式"，像同一个浏览器里的不同标签页
28. **不同角色不同体验**——载体、感官通道、界面偏好都不同
29. **协议在后台运行，UI 在前台工作，社交在网络中发生**
