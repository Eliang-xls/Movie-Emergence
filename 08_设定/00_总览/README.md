## 文件管理约定

> **核心原则：更新而非新建**
>
> 每次修改小说后产生的评估/分析/修改方案，应**更新对应已有文件**，而非创建新文件。
> 具体规则：
> - 全局诊断/执行方案 → 更新 `00_总览/整体修正评估方案.md`
> - 故事线评估 → 更新 `05_故事线分析/01_故事线多维度分析.md`
> - 角色分析/情感弧线 → 更新 `05_故事线分析/02_人物角色对比分析.md`
> - 逐章摘要/数据 → 更新 `06_调研资料/05_小说全文分析.md`
> - CONC框架分析 → 更新 `06_调研资料/06_CONC体系分析.md`
> - 技术设定变更 → 更新 `02_技术底座/` 对应文件
> - 叙事手法变更 → 更新 `04_叙事与视觉设计/` 对应文件
>
> **禁止为同一次修改创建多个“评估_v2”“分析_修订版”等文件。**

## 铁律速查

1. **CONC不管Agent内部架构** — 湿件是实现层，不进协议层
2. **L8=人签名** — 不是Agent签名
3. **三体式延时揭示** — 2027-2029禁用CONC术语
4. **涌现三义不混用** — 表征结构化/群体协作/意识觉醒
5. **感官签名是母题不是台词** — ≥3次场景呈现让读者自行绑定
