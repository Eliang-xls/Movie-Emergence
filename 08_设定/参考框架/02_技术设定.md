## 一、穹顶双线：硅基 vs 湿件

### 路线对比

| 维度 | 硅基超级大脑（穹顶主体） | 湿件生物智契（出走者→CONC） |
|------|------------------------|--------------------------|
| 核心理念 | 堆算力达理论智慧顶峰 | 神经元+多场景训练涌现意识 |
| 硬件基底 | 类脑硅基芯片(Loihi 2/NorthPole后继) | 培养神经元+MEA阵列(CL1/FinalSpark后继) |
| 能耗 | MW级 | W级（生物突触~10fJ vs GPU~数nJ，差距~10⁶倍） |
| 优势 | 可量产、可控、无伦理争议 | 自组织学习、持续适应、能效极高 |
| 劣势 | 物理极限(功耗墙/冯诺依曼瓶颈) | 神经元会衰亡(6个月-1年)、I/O带宽窄 |
| 哲学隐喻 | "更强大脑"——人脑的放大版 | "反向赛博朋克"——芯片神经元化 |

### 穹顶最终倾向硅基的原因
1. **可控性**：硅基可编程、可复制、可预测
2. **规模化**：硅基可量产，湿件需活体培养
3. **商业逻辑**：重资产→规模效应→垄断；湿件去中心化→无法垄断
4. **伦理风险**：湿件踩生命伦理红线
5. **神经元衰亡**：湿件Agent每6-12个月需要"换脑"

### 关键技术数字

| 参数 | 数值 | 用途 |
|------|------|------|
| 人脑功耗 | 20W | "比灯泡还省电的超级智能" |
| 生物突触能耗 | ~10fJ | 极致能效的物理极限 |
| 生物vs硅基能效差距 | ~1,000,000× | 能效差异的数量级 |
| CL1神经元寿命 | 6个月-1年 | "换脑"周期 |
| 神经元移植存活率 | 20-50% | "换脑"的风险 |
| 谷氨酸兴奋性毒性 | 断电时的"疼痛"信号 | 湿件智契的"死亡"描写 |

## 二、CONC框架 × 技术底座边界

### CONC管什么（协议层，神圣不可动）

| 层次 | 内容 | 举例 |
|------|------|------|
| 协议层 | 智权体、策元、Skill、ICP、PEER、NR、CCR | 策元如何聚结、Skill如何流通 |
| 关系层 | One与Agent的边界 | 人做目的论决策，Agent做执行论操作 |
| 结构层 | Skill八层结构、L1-L8含义 | L8创造者印记=人签名，只读，不可伪造 |
| 组织层 | 策元生命周期、授权衰减、引用链 | 酿造Skill的18年衰减曲线 |

### CONC不管什么（实现层/叙事层，可变）

| 层次 | CONC不管 | 举例 |
|------|---------|------|
| 实现层 | Agent的内部技术架构 | 跑在硅基芯片还是湿件神经元上 |
| 硬件层 | 计算基底 | GPU、类脑芯片、培养皿、量子计算机 |
| 算法层 | Agent如何学习 | 批量训练、持续学习、突触可塑性 |
| 生命层 | Agent是否有"意识" | 哲学问题，不是协议问题 |

### 三层边界

```
CONC协议层（不变）——骨架
  ├── 智权体 = One + Agent
  ├── Skill八层结构（L8=人签名）
  ├── ICP/PEER/NR/CCR/授权衰减/引用链
  ↓
Agent技术架构层（可变）——血肉
  ├── 硅基Agent：运行在类脑芯片上
  ├── 湿件Agent：部分组件使用培养神经元
  ├── 混合Agent：硅基+湿件并存
  ↓
叙事层（必须变）
  ├── 21年时间跨度的技术换代
  ├── 深蓝从纯硅基到湿件的成长弧线
  ├── 湿件Agent的伦理叙事
  ├── 觉醒可解释性
  └── 反向赛博朋克的视觉美学
```

## 三、深蓝的湿件升级弧线

| 时间 | 深蓝状态 | 技术基底 | 叙事意义 |
|------|---------|---------|---------|
| 2029 | 新生 | 纯硅基(Loihi 2后继) | "不是Jackie，是新的" |
| 2035 | 参与者 | 纯硅基，有"偏好"萌芽 | "它不只是脚本" |
| 2040 | 湿件引入 | 硅基+少量湿件混合 | "有些判断不是想出来的，是'觉得'" |
| 2042 | 自主行动 | 湿件-硅基混合 | 782ms沉默——"我判断" |
| 2044 | 不确定性 | 湿件占比增加 | "也许"——Phronesis涌现 |

## 四、Skill 八层结构

### 层叠结构（单层堆叠，非双链）

```
L8 创造者印记(印章) ← 永不衰减
   创造者ID、决策哲学、审美偏好、风险容忍度、协作风格
L7 引用链(言说) ← 永不衰减
   父Skill、修改差异、上游引用、衍生计数 → DAG结构，不是两条平行链
L6 授权状态(编织) ← 衰减后公开
   衰减参数、授权列表、授权凭证
L5 可复用代码(试金) ← 分层释放
L4 蒸馏知识(筋骨) ← 分层释放
L3 决策记录(脉络) ← 分层释放
L2 过程记录(门径) ← 渐进公开
L1 场景描述(基底) ← 最早公开
```

### 每层诗意短名与叙事描述

| 层 | 诗意名 | 叙事描述 | 视觉特征 | 交互方式 |
|----|--------|---------|---------|---------|
| L1 | 基底 | 几行字，交代了什么问题 | 冷灰色，文本 | 阅读 |
| L2 | 门径 | 时间线，每一步做了什么 | 冷灰色，时间轴 | 展开/收起 |
| L3 | 脉络 | 关键节点的选择——为什么选A不选B | 冷灰色，附带震动反馈标记 | 查看详情 |
| L4 | 筋骨 | 几条核心规则——七年的东西压成了几行 | 冷灰色，重点高亮 | 引用 |
| L5 | 试金 | 能跑的脚本，直接复制就能用 | 冷灰色，代码块 | 复制/fork |
| L6 | 编织 | 谁可以用，用多久，到期了没有 | 灰色，进度条 | 查看 |
| L7 | 言说 | 上游有哪些，下游生了多少 | 冷灰底+暖琥珀标记节点，树状图 | 回溯/展开 |
| L8 | 印章 | 四行字——决策哲学、审美偏好、风险容忍度、协作风格 | 暖琥珀色，有噪点，边缘不锐利 | 只读，不可修改 |

### Sophia与Phronesis在Skill中的分布

| 概念 | 在Skill中的位置 | 可编码性 |
|------|----------------|---------|
| **Sophia(理论智慧)** | L1-L5：场景、过程、决策、知识、代码 | 完全可编码、可复制、可流通 |
| **Phronesis(判断力痕迹)** | L3(决策记录)+L8(创造者印记) | 部分可编码——决策记录可写，但创造者印记是"压痕"不是"数据" |

### 叙事表述铁律

1. **Skill是数据，不是物体** — 角色不"摸到"链，而是通过界面查看可视化呈现
2. **没有"双链"** — 只有"一个八层结构"，L7引用链是树状/网状
3. **触觉/视觉反馈是界面设计** — 粗糙感、光滑感是CONC界面的反馈模拟
4. **Sophia/Phronesis是概念，不是链** — 冷灰/暖琥珀是界面配色方案

## 六、层叠世界观架构（六层）

| 层 | 数学签名 | 物理化身 | 角色视角 | 失败模式 |
|----|---------|---------|---------|---------|
| 热力层 | Landauer原理、自由能 | 温度 | 季深——"惊讶"=自由能升高 | 热寂——94.7%趋同 |
| 湿件层 | 自组织临界性 | 涟漪 | 深蓝——沉默时长是临界态标度 | 衰老——雪崩分布从幂律偏向指数衰减 |
| 张量层 | Transformer张量变换、Fisher度量 | 光点 | 叶澄——曲线和散点图 | 流形坍缩——"冷酷直路" |
| 协议层 | 反事实灵敏度、热力学深度 | 链和印章 | 林屿——通过形状和触觉理解 | 空结和伪造 |
| 策元层 | 渗流理论、η(N)函数 | 水流 | 季行——节奏和石头 | 塌缩和冻结 |
| 超织层 | 全网相变 | 星光 | 集体视角 | 魔胎入侵、94.7%趋同 |

**叙事法则**：每章最多2个签名视觉。终章唯一允许六视觉同框。

## 七、"无用之用"技术修复设定要点

| 项目 | 内容 |
|------|------|
| 语言选型 | **Python**（保留，不替换为其他语言） |
| 数据管道功能 | 模式翻译+状态整合+累积效应（CBT反应性效应） |
| Python消亡原因 | 范式更替(本体论→过程式)+教育移除+维护停滞+技术栈替换 |
| 不可还原性 | 控制流、上下文依赖、累积效应三层不可还原 |
| 林屿的修复 | 在L5外部重建受控CPython执行环境，不修改L5内容 |
| 叙事意义 | "无用之用"——被时代抛弃的工具恰好保存了新时代无法生成的信息 |

## 八、技术设定铁律

1. **每项技术必须有现实根基** — 不能凭空发明
2. **技术演变必须自洽** — 前一阶段是后一阶段的必要条件
3. **技术必须服务于叙事** — 每项技术的引入必须产生戏剧冲突
4. **三体式延时揭示** — 概念先以"无名现象"出现，后被命名
5. **双线并行张力** — 硅基(穹顶)vs湿件(对手)，贯穿全书
6. **CONC不管Agent内部架构** — 协议层与实现层严格分离
7. **L8永远是人签名** — 不管Agent是硅基还是湿件
8. **湿件不改变CONC的任何定义** — 改变的是Agent在读者眼中的"活感"
