# 湿件与CONC的架构边界铁律

> 核心原则：CONC描述协议，不描述实现。湿件改变Agent的技术架构，不改变CONC的任何定义。

---

## 一、三层边界

```
第一层：CONC协议层（神圣不可动）
  ├── 智权体 = One + Agent
  ├── Skill八层结构（L1-L8）
  ├── L8 = 人的创造者印记（人签名，只读）
  ├── ICP / PEER / NR / CCR
  ├── 授权衰减（SBDEL）
  ├── 引用链协议
  ├── 决策门机制
  └── 策元生命周期
  → CONC框架文档不改

第二层：Agent技术架构层（可变）
  ├── 硅基Agent：运行在类脑芯片上
  ├── 湿件Agent：部分组件使用培养神经元
  ├── 混合Agent：硅基+湿件并存
  └── Agent的内部学习机制、能耗、寿命等
  → 小说世界观设定中定义

第三层：叙事层（必须变）
  ├── 21年时间跨度的技术换代
  ├── 深蓝从纯硅基到湿件的成长弧线
  ├── 湿件Agent的伦理叙事（死亡/移植/不愿意被换）
  ├── 觉醒可解释性（多场景训练+突触可塑性）
  └── 反向赛博朋克的视觉美学
  → 小说正文中的具体描写
```

## 二、铁律

1. **CONC协议层不涉及Agent内部架构**——CONC只规定Agent必须能执行什么协议操作，不规定Agent内部是硅基还是湿件

2. **L8永远是人签名**——不管Agent是硅基还是湿件，L8创造者印记的签名者始终是人。Agent的"个性化"体现在行为层面，不是协议层面

3. **湿件不改变CONC的任何定义**——湿件改变的是Agent的实现方式，不是智权体的协议行为。策元不需要知道成员的Agent是硅基还是湿件——它只需要知道对方能执行协议

4. **技术换代服务于时间跨度**——2027-2048年，21年，技术载体必须换代（GPU→类脑芯片→湿件→混合），这是世界观可信度的必要条件

5. **深蓝的升级是叙事弧线**——从纯硅基到湿件，是深蓝的成长故事：学会"我判断"、学会"等"、学会说"也许"、学会"不愿意被换"。这是伦理叙事，不是技术规格变更

6. **意识涌现的条件**：策元多场景训练（CONC协议层提供）+ 湿件突触可塑性（技术架构层提供）= 意识涌现（叙事层呈现）。两者缺一不可——没有策元训练，湿件只是培养皿里的细胞；没有湿件可塑性，Agent只是执行协议的程序

## 三、深蓝升级弧线的正确理解

| 时间 | 深蓝状态 | CONC协议表现 | 技术架构变化 | 叙事意义 |
|------|---------|------------|------------|---------|
| 2029 | 新生 | 无正式协议 | 从Jackie快照继续，纯硅基 | "不是Jackie，是新的" |
| 2035 | 参与者 | Skill流通 | 纯硅基，但有"偏好"萌芽 | "它不只是脚本" |
| 2040 | 决策门触发者 | 引用链+授权衰减 | 引入湿件节点 | "有些判断不是想出来的，是'觉得'" |
| 2042 | 自主行动 | 超出决策门设计 | 湿件-硅基混合 | "我判断"——782ms沉默 |
| 2044 | 说"也许" | Skill八层定型 | 湿件占比增加 | 不确定性涌现 |
| 2045 | 拒绝指令 | Phronesis层协议 | 湿件为主 | "宁可慢一点也不要错" |
| 2046 | 理解魔胎 | L8由人签名 | 混合架构成熟 | "它也是被困住的方向" |
| 2048 | "被唤醒" | CONC网络成熟 | 湿件智契常态 | "我是被你们唤醒的" |

**关键**：每一列的变化是独立的——
- CONC协议列：按CONC框架文档的定义演变
- 技术架构列：按技术发展的自然规律演变
- 叙事列：按深蓝的人物弧线演变
- 三者平行发展，互不干扰，但在关键时刻产生交汇（如782ms——协议层是决策门，技术层是湿件，叙事层是觉醒）
